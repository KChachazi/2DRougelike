## 2. 核心修订

### 2.1 统一使用 PlayerInputHandler 输入

#### 设计结果

- `PlayerInputHandler` 是项目中唯一读取键盘、鼠标和相机输入的组件。
- `PlayerController` 只接收已经解释完成的移动与瞄准结果，不再依赖 Input System。
- `Keyboard.current` 与 `Mouse.current` 只存在于 `PlayerInputHandler.cs`。
- 玩家朝向、移动速度、开火和状态机行为保持不变。

#### PlayerController.cs

目标文件：

```text
Assets/Scripts/Entities/PlayerController.cs
Reference/Scripts/Entities/PlayerController.cs
```

删除 `UnityEngine.InputSystem`、主相机缓存以及 `RotateTowardsMouse()`。`PlayerController` 改为暴露接收世界空间瞄准方向的能力：

```csharp
/// <summary>接收输入层计算好的世界空间瞄准方向并旋转刚体。</summary>
public void SetAimDirection(Vector2 direction)
{
    if (direction.sqrMagnitude < 0.0001f) return;
    Rb.rotation = Mathf.Atan2(direction.y, direction.x) * Mathf.Rad2Deg;
}
```

移动仍然必须保留状态异常倍率：

```csharp
public void Move(float speed)
{
    float multiplier = StatusEffectManager != null
        ? StatusEffectManager.SpeedMultiplier
        : 1f;
    Rb.MovePosition(
        Rb.position + MoveInput * speed * multiplier * Time.fixedDeltaTime);
}
```

#### PlayerInputHandler.cs

目标文件：

```text
Assets/Scripts/Commands/PlayerInputHandler.cs
Reference/Scripts/Commands/PlayerInputHandler.cs
```

`PlayerInputHandler` 在 `Awake()` 缓存 `Camera.main`，并在 `Update()` 中按照“移动 → 瞄准 → 持续开火”的顺序读取输入：

```csharp
ReadMove();
ReadAim();

```

瞄准输入在这里完成屏幕坐标到世界坐标的转换：

```csharp
private void ReadAim()
{
    Mouse mouse = Mouse.current;
    if (mouse == null || mainCamera == null) return;

    Vector2 screenPosition = mouse.position.ReadValue();
    Vector3 worldPosition = mainCamera.ScreenToWorldPoint(new Vector3(
        screenPosition.x,
        screenPosition.y,
        -mainCamera.transform.position.z));

    player.SetAimDirection((Vector2)worldPosition - player.Rb.position);
}
```

这次调整正式确立了“输入层读取设备，Controller 只暴露能力”的边界。

### 2.2 异常状态合并规则深化

整理前，所有同类型状态倾向于统一使用“简单续时”。整理后，不同状态根据自身语义采用不同规则。

#### Freeze

- 相同减速比例：只延长剩余时间。
- 不同减速比例：允许同时存在。
- `SpeedMultiplier` 始终取全部 Freeze 中最慢的结果。

#### Vulnerable

- 相同受伤倍率：只延长剩余时间。
- 不同受伤倍率：允许同时存在。
- `DamageMultiplier` 始终取全部 Vulnerable 中最高的结果。

#### Burn

同一实体同时只保留一个灼烧效果：

1. 单次伤害和 Tick 间隔相同时，只延长剩余时间，并保留当前 Tick 进度。
2. 参数不同时，比较旧效果剩余总伤与新效果完整总伤，保留总伤更高的一方。
3. 总伤相同时，保留剩余持续时间更短的一方，使相同总伤更快结算完毕。
4. 新效果替换旧效果后，从新效果的完整 Tick 间隔重新计时。

`ApplyEffect()` 现在只负责编排：

```text
配置校验 → 查找同类型效果 → 尝试合并 → 添加新效果
```

具体规则拆分到以下私有方法：

- `TryMergeEffect()`：按状态类型分派合并规则。
- `MergeBurn()`：处理灼烧续时、剩余总伤比较与替换。
- `ExtendDuration()`：为同强度 Freeze/Vulnerable 续时。
- `CalculateRemainingBurnDamage()`：结合剩余时间与下一次 Tick 计时计算灼烧剩余总伤。
- `IsValidConfig()`：拒绝非正持续时间、无效灼烧参数、超出 `(0, 1]` 的减速比例和未知状态类型。

DoT 的逐帧计时方式保持不变：每个 `Update` 最多结算一次 Tick，结算后把计时器重置为完整间隔。本轮不处理极端低帧率下的 Tick 漂移或追帧补算。

## 3. 注释补充

### 3.1 基本规则

- 每个公开类型至少提供一个 `<summary>`。
- `<summary>` 面向调用方，只说明职责、结果和重要约束。
- 实现步骤、内部流程与算法细节使用普通 `//`，避免让悬浮摘要过长。
- 对外能力或容易误用的方法补充 `<summary>`。
- Unity 生命周期函数、简单 getter、接口中已经明确约定的方法和显而易见的赋值不逐个解释。
- 不在 Action 节点中重复外层行为树条件已经保证的前提。
- 注释必须描述当前真实语义，尤其注意复制粘贴后的类型名、属性/方法括号和可选行为。
- Inspector 中容易误配的序列化字段优先使用 `[Tooltip]` 说明单位、特殊值和约束。
