# V1.5-2：敌人 AI 深化 —— 行为树 + 多敌人类型 + Boss 多阶段

> V1.5-1 我们把"伤害"做成了可以叠加元素效果的伤害包（灼烧/冰冻/击退）。这一阶段轮到**敌人 AI**——现有敌人是固定 4 态 FSM（Patrol/Chase/Attack/Dead），所有敌人都一样，换个敌人类型只能改数值。
>
> 这阶段的武器是**行为树（Behavior Tree）**：用可组合的节点代替硬编码的状态转换。配合数据驱动（EnemyBehavior SO），能轻松做出"近战贴身砍 / 远程保持距离射击 / 自爆冲脸 / Boss 半血换技能"四种完全不同的敌人。
>
> 照旧：分 4 步，每步可编译、可 Play 验收。参考实现在 `Reference/Scripts/...`，你自己在 `Assets/Scripts/...` 对应路径创建/替换。不懂随时问。

## 本周目标

- **行为树框架**：`Node` / `Sequence` / `Selector` / `Decorator` / `Condition` / `Action` / `Blackboard`，一套通用决策逻辑。
- **多敌人类型**：近战（贴身砍）、远程（保持距离射击）、自爆（冲脸引爆），全部由 `EnemyBehavior` SO 数据驱动。
- **Boss 多阶段**：血量阈值切阶段、阶段技能池、技能附带灼烧（复用 V1.5-1 的状态异常系统）。
- **架构分层**：行为树管"主动决策"，状态机只管"被动打断"（击退/死亡）——两者不抢活。

完成后：房间里能摆三种敌人（近战/远程/自爆），Boss 打一半会变强换技能，敌人被击退/打死后行为树自动暂停。V1 的所有功能保持不变。

## 0. 先理解：行为树是什么、为什么用它

### 0.1 FSM 的痛点

你现在是 4 态 FSM。敌人行为一变复杂，状态类就开始爆炸。比如：

- 远程敌人要"太近就后退 / 距离合适就射击 / 太远就追击"——三个状态互相跳
- Boss 要"半血前用技能 A / 半血后用技能 B"——状态里加 if
- 每种敌人一套 FSM，近战/远程/自爆/Boss = 4 套状态类 × 4 组转换条件

FSM 的状态和转换条件**写死在类里**，很难复用。行为树的价值在于：**把"决策"拆成可组合的小节点**，不同的敌人 = 不同的节点组合。

### 0.2 行为树的三个核心概念

**① 节点（Node）**：每帧 `Evaluate()`，返回三种结果之一：

| 返回值 | 含义 |
|--------|------|
| `Running` | 正在执行（动作需要多帧，如移动/攻击前摇） |
| `Success` | 成功（条件成立 / 动作完成） |
| `Failure` | 失败（条件不成立 / 动作做不了） |

**② 组合节点（Composite）**——决定子节点的执行方式：

- **`Sequence`（顺序/AND）**：全部子节点成功才成功，遇到失败立即短路。
  ```
  Sequence [ 在视野? → 在攻击范围? → 攻击 ]   // 三个都过才攻击
  ```
- **`Selector`（选择/OR）**：任一子节点成功就成功，从第一个开始找能用的。
  ```
  Selector [ 攻击分支, 追击分支, 巡逻分支 ]     // 能攻击就攻击，否则追，再否则巡逻
  ```
- **`Inverter`（取反）**：Success ↔ Failure。表达"不在范围才……"。
- **`Cooldown`（冷却）**：子节点成功后进入冷却，冷却期间跳过。

**③ 叶子节点**：
- **`Condition`（条件）**：只判断，返回 Success/Failure（瞬时）。
- **`Action`（动作）**：执行行为，可多帧 Running（追/巡逻）。

还有**`Blackboard`（黑板）**：节点间共享数据的字典（比如玩家引用）。

### 0.3 一棵近战敌人树长什么样

```
Selector（从高优先级往低试）
├── 攻击分支  Sequence [ InSight? → InAttackRange? → MeleeAttack ]
├── 追击分支  Sequence [ InSight? → Chase ]
└── 巡逻分支  Patrol
```

每帧从根开始评估：
- 玩家在攻击范围 → 攻击分支成功（其他分支不执行）
- 玩家在视野但远 → 攻击分支失败（InAttackRange 不成立）→ 落追击分支 → Running
- 玩家消失 → 攻击/追击都失败 → 落巡逻分支 → Running

**你发现了吗**：这颗树同时表达了 FSM 的"Patrol→Chase→Attack"状态跳转，但不需要状态类、不需要转换条件表——**行为就是树的形状**。换敌人类型 = 换一棵树。

```csharp
namespace Game.AI
{
    /// <summary>
    /// 行为树节点的三种返回值。
    ///
    ///   Running —— 正在执行（动作需要多帧，如移动/攻击前摇）
    ///   Success —— 成功（条件成立 / 动作完成）

        Running,
        Success,
        Failure,
    }
```

### 1.3 新建 `Assets/Scripts/AI/Node.cs`

参考实现：`Reference/Scripts/AI/Node.cs`。

```csharp
namespace Game.AI
{
    /// <summary>
    /// 行为树节点抽象基类。
    ///
    /// 一切节点（组合、装饰、条件、动作）都继承自它，
    /// 唯一的接口是 Evaluate()——每帧调用一次，返回 NodeState。
    ///
    /// 设计要点：
    ///   - Node 本身不持有任何子节点引用（组合节点才持有）
    ///   - State 记录本节点最近一次 Evaluate 的结果（调试/观察用）
    ///   - 纯 C# 类，不是 MonoBehaviour——行为树是"决策逻辑"，不该挂场景上
    /// </summary>
    public abstract class Node
    {
        /// <summary>本节点最近一次 Evaluate 的返回值（只读，供调试）</summary>
        public NodeState State { get; protected set; }

        /// <summary>
        /// 评估本节点。父节点每帧调用一次。
        /// 子类必须实现。
        /// </summary>
        public abstract NodeState Evaluate();

        /// <summary>重置节点状态（重新开始时调用）</summary>
        public void Reset() => State = NodeState.Running;
    }
}
```

### 1.4 新建 `Assets/Scripts/AI/CompositeNode.cs`

参考实现：`Reference/Scripts/AI/CompositeNode.cs`。

```csharp
using System.Collections.Generic;

namespace Game.AI
{
    /// <summary>
    /// 组合节点基类——持有若干子节点，决定它们的执行方式。
    ///
    /// 它是 Sequence / Selector 的共同父类。
    /// 用 params 构造，方便一行搭一棵树：
    ///   new SelectorNode(a, b, c)  —— 三个子节点
    /// </summary>
    public abstract class CompositeNode : Node
    {
        /// <summary>子节点列表（按顺序执行）</summary>
        protected readonly List<Node> children = new List<Node>();

        protected CompositeNode(params Node[] childNodes)
        {
            if (childNodes != null)
                children.AddRange(childNodes);
        }

        /// <summary>运行时动态添加子节点（可选）</summary>
        public void AddChild(Node child) => children.Add(child);
    }
}
```

### 1.5 新建 `Assets/Scripts/AI/SequenceNode.cs`

参考实现：`Reference/Scripts/AI/SequenceNode.cs`。

```csharp
namespace Game.AI
{
    /// <summary>
    /// 顺序节点（AND）——所有子节点都要成功，整体才成功。
    ///
    /// 语义：依次执行子节点，逐个检查。
    ///   - 遇到 Running → 返回 Running（当前的还在跑，后面的还没开始）
    ///   - 遇到 Failure → 返回 Failure（立刻短路，后面的不执行）
    ///   - 全部 Success → 返回 Success
    ///
    /// 典型用途：表达"先判断再行动"的链——
    ///   Sequence [ 在视野? → 在攻击范围? → 攻击 ]
    /// </summary>
    public class SequenceNode : CompositeNode
    {
        public SequenceNode(params Node[] childNodes) : base(childNodes) { }

        public override NodeState Evaluate()
        {
            foreach (Node child in children)
            {
                NodeState childState = child.Evaluate();
                if (childState != NodeState.Success)
                    return State = childState; // Running 或 Failure，短路
            }
            return State = NodeState.Success;
        }
    }
}
```

```csharp
namespace Game.AI
{
    /// <summary>
    /// 选择节点（OR）——任一子节点成功，整体就成功。
    ///
    /// 语义：依次尝试子节点，找到第一个可行的就执行。
    ///   - 遇到 Running → 返回 Running（这个正在执行）
    ///   - 遇到 Success → 返回 Success（立刻短路，后面的不执行）
    ///   - 全部 Failure → 返回 Failure（没有可选分支）
    ///
    /// 典型用途：表达"决策优先级"——
    ///   Selector [ 攻击分支, 追击分支, 巡逻分支 ]
    ///   优先级从高到低：能攻击就攻击，不行就追，再不行就巡逻。
    /// </summary>
    public class SelectorNode : CompositeNode
    {
        public SelectorNode(params Node[] childNodes) : base(childNodes) { }

        public override NodeState Evaluate()
        {
            foreach (Node child in children)
            {
                NodeState childState = child.Evaluate();
                if (childState != NodeState.Failure)
                    return State = childState; // Running 或 Success
            }
            return State = NodeState.Failure;
        }
    }
}
```

参考实现：`Reference/Scripts/AI/InverterNode.cs`。

```csharp
namespace Game.AI
{
    /// <summary>
    /// 取反装饰器（NOT）——包装一个子节点，把它的结果反过来。
    ///
    ///   Success → Failure
    ///   Failure → Success
    ///   Running → Running
    ///
    /// 典型用途：表达"不在范围才……"这类否定条件。
    ///   例如"玩家不在攻击范围" = Inverter( InAttackRange )
    /// </summary>
    public class InverterNode : Node
    {
        private readonly Node child;

        public InverterNode(Node child)
        {
            this.child = child;
        }

        public override NodeState Evaluate()
        {
            NodeState childState = child.Evaluate();
            if (childState == NodeState.Success) return State = NodeState.Failure;
            if (childState == NodeState.Failure) return State = NodeState.Success;
            return State = NodeState.Running;
        }
    }
}
```

### 1.8 新建 `Assets/Scripts/AI/CooldownNode.cs`

参考实现：`Reference/Scripts/AI/CooldownNode.cs`。

```csharp
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 冷却装饰器——包装一个子节点，子节点"成功"后进入冷却。
    /// 冷却期间子节点被跳过，直接返回 Failure。
    ///
    /// 典型用途：给技能/攻击动作加冷却——
    ///   Cooldown( 攻击Action, 1f )   —— 每次攻击后 1 秒内无法再攻击
    ///
    /// 注意：只有子节点返回 Success（真正放了技能）才进入冷却；
    /// 返回 Failure（条件不满足，没放出来）不触发冷却，下次还能再试。
    /// </summary>
    public class CooldownNode : Node
    {
        private readonly Node child;
        private readonly float cooldownDuration;
        private float timer;

        public CooldownNode(Node child, float cooldownDuration)
        {
            this.child = child;
            this.cooldownDuration = cooldownDuration;
        }

        public override NodeState Evaluate()
        {
            if (timer > 0f)
            {
                timer -= Time.deltaTime;
                return State = NodeState.Failure; // 冷却中，技能不可用
            }

            NodeState childState = child.Evaluate();
            if (childState == NodeState.Success)
                timer = cooldownDuration; // 成功放了一次技能 → 进入冷却

            return State = childState;
        }
    }
}
```

```csharp
namespace Game.AI
{
    /// <summary>
    /// 条件节点抽象基类——只做判断，不做动作。
    ///
    /// 子类只需要实现 Check()，返回 true/false。
    /// Evaluate() 已经写死：true → Success，false → Failure。
    /// 条件节点永不返回 Running（判断是瞬时的）。
    ///
    /// 典型子类：
    ///   InSightCondition  —— 玩家在视野内？
    ///   InAttackRangeCondition —— 玩家在攻击范围内？
    /// </summary>
    public abstract class ConditionNode : Node
    {
        public override NodeState Evaluate()
        {
            return State = Check() ? NodeState.Success : NodeState.Failure;
        }

        /// <summary>子类实现：判断条件是否成立</summary>
        protected abstract bool Check();
    }
}
```

```csharp
using System.Collections.Generic;

namespace Game.AI
{
    /// <summary>
    /// 黑板（Blackboard）——行为树各节点共享的"聊天板"。
    ///
    /// 为什么需要它：
    ///   行为树节点是独立的对象，但它们经常要共享数据——
    ///   比如"玩家的引用"、某个 Condition 算出的"玩家是否可见"、
    ///   巡逻节点的"当前目标点"。黑板就是这些数据的集中存放处。
    ///
    /// 设计为 Dictionary&lt;string, object&gt;：用字符串键存取。
    /// 简单直接，够用即可（不引入复杂类型系统）。
    /// </summary>
    public class Blackboard
    {
        private readonly Dictionary<string, object> values = new Dictionary<string, object>();

        /// <summary>写入/覆盖一个值</summary>
        public void Set(string key, object value)
        {
            values[key] = value;
        }

        /// <summary>读取一个值。若不存在返回 null。</summary>
        public T Get<T>(string key) where T : class
        {
            return values.TryGetValue(key, out object value) ? (T)value : null;
        }

        /// <summary>是否已有该键</summary>
        public bool Has(string key) => values.ContainsKey(key);

        /// <summary>清空全部（实体重置/死亡时调用）</summary>
        public void Clear() => values.Clear();
    }
}
```

```csharp
namespace Game.AI
{
    /// <summary>
    /// 行为树本体——持有根节点 + 黑板。
    ///
    /// 使用方式：
    ///   1. 构造一棵树（用 Sequence/Selector/Condition/Action 组合）
    ///   2. 每帧调用 Evaluate()，从根节点开始向下评估
    ///
    /// 典型构造（在 EnemyBrain 里）：
    ///   BehaviorTree tree = new BehaviorTree(blackboard,
    ///       new SelectorNode(
    ///           new AttackSequence(...),
    ///           new ChaseAction(...),
    ///           new PatrolAction(...)
    ///       ));
    /// </summary>
    public class BehaviorTree
    {
        /// <summary>整棵树共享的黑板</summary>
        public Blackboard Blackboard { get; }

        private readonly Node root;

        public BehaviorTree(Blackboard blackboard, Node root)
        {
            Blackboard = blackboard;
            this.root = root;
        }

        /// <summary>从根节点开始评估整棵树。每帧调用一次。</summary>
        public NodeState Evaluate() => root.Evaluate();
    }
}
```

### 1.13 新建 `Assets/Scripts/AI/BehaviorTreeTester.cs`（演示用）

参考实现：`Reference/Scripts/AI/BehaviorTreeTester.cs`。

这个组件让步骤 1 能"跑起来验收"。挂任意 GameObject 上，用一棵模拟敌人 AI 的小树演示行为树怎么切换节点。

```csharp
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 步骤 1 的演示组件——挂任意 GameObject 上，
    /// 用一棵模拟敌人 AI 的小行为树，演示行为树怎么跑。
    ///
    /// 这棵树模拟一个"敌人"：
    ///   距离近 → 攻击
    ///   距离远 → 巡逻
    ///   距离会每帧随机变化，可以看到节点在两种行为间切换。
    ///
    /// 用 Console 观察输出（勾选 Console 的 Collapse 折叠重复日志更清楚）。
    /// 用完可以删除这个组件——它不是游戏逻辑，只是教学演示。
    ///
    /// 重点看节点是怎么拿到数据的：
    ///   这里通过"构造函数注入"——节点构造时传入数据源（本组件），
    ///   直接从它读 fakeDistance。这和步骤 2 里
    ///   "敌人节点构造时传入 EnemyController，从它读数据"是同一个模式。
    /// </summary>
    public class BehaviorTreeTester : MonoBehaviour
    {
        /// <summary>模拟的"玩家距离"（每帧随机跳变，制造条件变化）</summary>
        public float FakeDistance { get; private set; } = 5f;

        private BehaviorTree tree;

        private void Awake()
        {
            tree = new BehaviorTree(new Blackboard(), BuildDemoTree());
        }

        private void Update()
        {
            // 模拟距离随机变化：3~8 之间跳动，制造"时近时远"
            FakeDistance = 3f + Random.value * 5f;
            tree.Evaluate();
        }

        /// <summary>模拟敌人 AI 的小树：近→攻击，远→巡逻</summary>
        private Node BuildDemoTree()
        {
            return new SelectorNode(
                // 分支 1：玩家很近 → 攻击
                new SequenceNode(
                    new DistanceBelowCondition(this, 3.5f),
                    new LogAction("⚔️ 攻击！")
                ),
                // 分支 2：否则巡逻
                new LogAction("🚶 巡逻...")
            );
        }

        // ---------- 演示用节点（真实敌人项目里不这么写，只为了教学） ----------

        /// <summary>条件：玩家距离低于阈值</summary>
        private class DistanceBelowCondition : ConditionNode
        {
            private readonly BehaviorTreeTester host;
            private readonly float threshold;

            public DistanceBelowCondition(BehaviorTreeTester host, float threshold)
            {
                this.host = host;
                this.threshold = threshold;
            }

            protected override bool Check() => host.FakeDistance < threshold;
        }

        /// <summary>动作：打印一条日志，返回 Success</summary>
        private class LogAction : ActionNode
        {
            private readonly string message;
            public LogAction(string message) { this.message = message; }

            public override NodeState Evaluate()
            {
                Debug.Log(message);
                return NodeState.Success;
            }
        }
    }
}
```

> **为什么节点用构造函数注入数据源**：`DistanceBelowCondition` 构造时拿到 `host`（本组件），`Check()` 里读 `host.FakeDistance`。这是行为树节点获取数据的标准方式——步骤 2 里节点构造时注入 `EnemyController`，从它读数据、调它的方法。黑板目前只存 enemy 引用备用，节点主要用构造注入（更直白）。

## 步骤 2：近战敌人行为树化

**这一步做什么**：把现有近战敌人从"4 态 FSM"改成"行为树驱动"。这是最核心的重构一步——做完**敌人的行为应该和原来一模一样**（巡逻→追击→攻击→被击退暂停），但代码结构完全不同了。

> ⚠️ 这一步改动很大，涉及重构 `EnemyController`。建议先复制一份 `Reference/Scripts/Entities/EnemyController.cs` 对照着改，别凭记忆敲。

### 2.1 先理解：EnemyController 的角色变化

**重构前**（V1.5-1）：

```
EnemyController = 上下文 + 持有 4 态 FSM（Patrol/Chase/Attack/Dead + Knockback）
                 Patrol/Chase/Attack 状态类里写行为逻辑
```

**重构后**（V1.5-2）：

```
EnemyController = 被动打断中心 + 上下文（只留 Free / Knockback / Dead）
EnemyBrain      = 主动决策（每帧跑行为树，巡逻/追击/攻击全在树里）
```

**为什么拆**：Patrol/Chase/Attack 三个状态是"主动决策"（敌人自己决定干什么），这些交给行为树；Knockback/Dead 是"被动打断"（敌人被打了必须停），这些保留在状态机。两个系统各管一摊，用 `IsActionLocked` 协调——被击退/死亡时行为树暂停。

```csharp
using Game.StateMachines;
using Game.StateMachines.Enemy;

        public Vector2 KnockbackDirection { get; private set; }

        /// EnemyBrain 每帧检查它——为真则行为树暂停，等打断结束。
        /// </summary>
        public bool IsActionLocked =>
            stateMachine.CurrentState == KnockbackState || stateMachine.CurrentState == DeadState;

        private readonly StateMachine stateMachine = new StateMachine();

        private void Awake()
        {
            Rb = GetComponent<Rigidbody2D>();
            health = GetComponent<Health>();
            SpriteRenderer = GetComponent<SpriteRenderer>();

            health.Died += OnDied;

        private void OnDisable()
        {
            health.Damaged -= OnDamaged;
            health.Died -= OnDied;
        }

        {

            if (playerObj != null)
                Player = playerObj.transform;

            stateMachine.ChangeState(FreeState);
        }

        private void Update()
        {
            stateMachine.Tick();
        }

        private void FixedUpdate()
        {
            stateMachine.FixedTick();
        }

        public float DistanceToPlayer()
        {
            return Player == null ? float.MaxValue : Vector2.Distance(Rb.position, Player.position);

        }

        private void OnDied()
        {
            EventBus.Publish(new EnemyDiedEvent(Rb.position));
            stateMachine.ChangeState(DeadState);
        }
    }
```

### 2.5 修改 `Assets/Scripts/StateMachines/Enemy/EnemyKnockbackState.cs`

参考实现：`Reference/Scripts/StateMachines/Enemy/EnemyKnockbackState.cs`。

**只改一处**：击退结束后回 `FreeState` 而不是 `PatrolState`（因为主动行为已经交给行为树了）。

```csharp
using Game.Entities;
using UnityEngine;

namespace Game.StateMachines.Enemy
{
    /// <summary>
    /// 击退状态——敌人被命中后短暂推开、不能做任何主动行为。
    ///
    /// V1.5-2 变化：结束后回 FreeState（而不是 PatrolState）——
    /// 因为主动行为（巡逻/追击/攻击）已经交给行为树，
    /// 击退结束意味着"行为树可以继续运行了"。
    /// </summary>
    public class EnemyKnockbackState : IState
    {
        private readonly EnemyController enemy;
        private readonly StateMachine stateMachine;
        private float timer;
        private Vector2 direction;
        private float startSpeed;

        public EnemyKnockbackState(EnemyController enemy, StateMachine stateMachine)
        {
            this.enemy = enemy;
            this.stateMachine = stateMachine;
        }

        public void Enter()
        {
            direction = enemy.KnockbackDirection;
            startSpeed = enemy.KnockbackSpeed;
            timer = 0f;
            enemy.SpriteRenderer.color = Color.cyan;  // 调试色：击退时闪青
        }

        public void Tick() { }

        public void FixedTick()
        {
            timer += Time.fixedDeltaTime;
            if (timer >= enemy.KnockbackDuration)
            {
                stateMachine.ChangeState(enemy.FreeState); // 回到自由态，行为树接管
                return;
            }

            // 速度线性衰减：开始最快 → 逐渐减速 → 自然停止
            float t = timer / enemy.KnockbackDuration;
            float currentSpeed = Mathf.Lerp(startSpeed, 0f, t);
            enemy.Rb.MovePosition(
                enemy.Rb.position + direction * currentSpeed * Time.fixedDeltaTime);
        }

        public void Exit()
        {
            enemy.SpriteRenderer.color = enemy.OriginalColor;
        }
    }
}
```

**`PatrolAction.cs`** —— 参考实现：`Reference/Scripts/AI/Enemy/PatrolAction.cs`。

```csharp
using Game.Entities;
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 动作：在出生点附近随机巡逻。
    ///
    /// 走到目标点 → 等待 1 秒 → 选新目标 → 继续走。返回 Running（永远在巡逻）。
    /// 对应原 FSM 的 PatrolState。
    /// </summary>
    public class PatrolAction : ActionNode
    {
        private const float WaitDuration = 1f;

        private readonly EnemyController enemy;
        private readonly EnemyBehavior behavior;
        private Vector2 wanderTarget;
        private float waitTimer;

        public PatrolAction(EnemyController enemy, EnemyBehavior behavior)
        {
            this.enemy = enemy;
            this.behavior = behavior;
            PickNewTarget();
        }

        public override NodeState Evaluate()
        {
            if (Vector2.Distance(enemy.Rb.position, wanderTarget) < 0.1f)
            {
                // 已到达目标点 → 原地等待，然后换新目标
                waitTimer += Time.deltaTime;
                if (waitTimer >= WaitDuration)
                    PickNewTarget();
            }
            else
            {
                enemy.MoveTowards(wanderTarget, behavior.patrolSpeed);
            }
            return NodeState.Running;
        }

        private void PickNewTarget()
        {
            Vector2 offset = Random.insideUnitCircle * behavior.patrolRadius;
            wanderTarget = enemy.SpawnPosition + offset;
            waitTimer = 0f;
        }
    }
}
```

```csharp
using Game.Entities;
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 动作：近战攻击玩家（贴身扣血）。
    ///
    /// 三段式行为：
    ///   冷却中 → Running（锁定攻击姿态，不切换分支）
    ///   冷却结束 → 扣血 + 进入冷却 → Success
    ///   玩家不存在 → Failure
    ///
    /// 冷却由节点自己管理（对应原 FSM 里 AttackState 的 attackCooldown）。
    /// </summary>
    public class MeleeAttackAction : ActionNode
    {
        private readonly EnemyController enemy;
        private readonly EnemyBehavior behavior;
        private float cooldownTimer;

        public MeleeAttackAction(EnemyController enemy, EnemyBehavior behavior)
        {
            this.enemy = enemy;
            this.behavior = behavior;
        }

        public override NodeState Evaluate()
        {
            // 冷却中：保持攻击姿态（Running），不跳到追击/巡逻分支
            if (cooldownTimer > 0f)
            {
                cooldownTimer -= Time.deltaTime;
                return NodeState.Running;
            }

            if (enemy.Player != null && enemy.Player.TryGetComponent(out Health health))
            {
                health.TakeDamage(behavior.contactDamage);
                cooldownTimer = behavior.attackCooldown;
                return NodeState.Success;
            }
            return NodeState.Failure;
        }
    }
}
```

> **为什么 MeleeAttackAction 冷却中返回 Running 而不是 Failure**：返回 Running 表示"我还在攻击姿态里"，Selector 会停留在攻击分支；返回 Failure 会让 Selector 跳到追击分支（敌人会原地空追）。Running 更贴近原 FSM 里"攻击后摇期间锁定攻击状态"的行为。

### 2.7 新建 `Assets/Scripts/Entities/EnemyBrain.cs`

参考实现：`Reference/Scripts/Entities/EnemyBrain.cs`。

这是 V1.5-2 的**核心组件**——它持有行为树 + 黑板，每帧驱动它。挂载在敌人预制体上（EnemyController 的兄弟组件）。

```csharp
using Game.AI;
using Game.Core;
using UnityEngine;

namespace Game.Entities
{
    /// <summary>
    /// 敌人"大脑"——持有行为树 + 黑板，每帧驱动它。
    ///
    /// V1.5-2 的核心组件：它把"敌人该干什么"从 FSM 换成行为树。
    ///
    /// 分工：
    ///   EnemyBrain     —— 主动决策（每帧 Evaluate 行为树：巡逻/追击/攻击/技能）
    ///   EnemyController—— 被动打断 + 上下文（击退/死亡暂停，移动/数据工具）
    ///
    /// 暂停规则：敌人被击退/死亡时（enemy.IsActionLocked），
    /// 行为树不评估——等打断结束（回到 FreeState）再继续。
    ///
    /// 挂载：每个敌人预制体上（EnemyController 的兄弟组件）。
    /// 远程/自爆/Boss 敌人需要拖入一个 EnemyProjectile 的对象池引用。
    /// </summary>
    [RequireComponent(typeof(EnemyController))]
    public class EnemyBrain : MonoBehaviour
    {
        [Tooltip("敌人子弹池（远程/Boss 用）。预制体需包含 ObjectPool 引用 EnemyProjectile")]
        [SerializeField] private ObjectPool enemyProjectilePool;

        private EnemyController enemy;
        private Blackboard blackboard;
        private BehaviorTree tree;

        private void Awake()
        {
            enemy = GetComponent<EnemyController>();
            blackboard = new Blackboard();
            blackboard.Set("enemy", enemy); // 节点可从黑板取 enemy（当前用构造注入，黑板备用）
            tree = BuildTree(enemy.Behavior);
        }

        private void Update()
        {
            // 被击退/死亡时暂停行为树，让状态机处理打断
            if (enemy.IsActionLocked) return;
            tree.Evaluate();
        }

        // ==================== 树构建 ====================

        /// <summary>
        /// 根据 EnemyBehavior.type 构建对应类型的树。
        /// 换敌人类型 = 换 Behavior 资产，这里 switch 决定树结构。
        /// </summary>
        private BehaviorTree BuildTree(EnemyBehavior behavior)
        {
            switch (behavior.type)
            {
                case EnemyType.Melee:  return BuildMeleeTree(behavior);
                case EnemyType.Ranged: return BuildRangedTree(behavior);
                case EnemyType.Bomber: return BuildBomberTree(behavior);
                case EnemyType.Boss:   return BuildBossTree(behavior);
                default:               return BuildMeleeTree(behavior);
            }
        }

        /// <summary>
        /// 近战敌人树：
        ///   攻击（在视野且近身）> 追击（在视野）> 巡逻
        /// </summary>
        private BehaviorTree BuildMeleeTree(EnemyBehavior b)
        {
            Node root = new SelectorNode(
                new SequenceNode(
                    new InSightCondition(enemy, b),
                    new InAttackRangeCondition(enemy, b),
                    new MeleeAttackAction(enemy, b)
                ),
                new SequenceNode(
                    new InSightCondition(enemy, b),
                    new ChaseAction(enemy, b)
                ),
                new PatrolAction(enemy, b)
            );
            return new BehaviorTree(blackboard, root);
        }

        // 以下类型在步骤 3 / 步骤 4 实现（当前先返回近战树，保证可编译）
        private BehaviorTree BuildRangedTree(EnemyBehavior b) => BuildMeleeTree(b);
        private BehaviorTree BuildBomberTree(EnemyBehavior b) => BuildMeleeTree(b);
        private BehaviorTree BuildBossTree(EnemyBehavior b) => BuildMeleeTree(b);
    }
}
```

> **EnemyBrain 的关键逻辑**：
> - `Awake` 里从 `enemy.Behavior` 读类型，`BuildTree` switch 决定构建哪棵树。**这就是"换敌人类型 = 换 SO"的魔法发生的地方**——类型变了，树的形状就变了。
> - `Update` 里先查 `enemy.IsActionLocked`——被击退/死亡就跳过 Evaluate（行为树暂停），状态机自己跑打断。
> - 现在 BuildRangedTree 等还是返回近战树（占位），步骤 3/4 会补上真正的实现。

```csharp
            rb = GetComponent<Rigidbody2D>();
            damageInfo = new DamageInfo(fallbackDamage);
        }

        private void OnEnable()
        {
            timer = 0f;
        }

        /// <summary>
        /// 发射——从池取出后调用，一次性设置所有参数。
        /// </summary>

        {
            transform.SetPositionAndRotation(position, rotation);
            this.speed = speed;
            damageInfo = info;
        }

        private void FixedUpdate()
        {
            rb.linearVelocity = transform.right * speed;
            timer += Time.fixedDeltaTime;
            if (timer >= lifeTime)
                ReturnToPool();
        }

        private void OnTriggerEnter2D(Collider2D other)
        {
            if (!other.CompareTag("Player")) return;

            ReturnToPool();

        {
            rb.linearVelocity = Vector2.zero;
            if (Pool != null)
                Pool.Release(gameObject);
            else
                Destroy(gameObject);
```

```csharp
using Game.Entities;
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 动作：远离玩家（后退）——远程敌人被贴脸时的应对。
    ///
    /// 朝"玩家 → 自己"的方向后退，返回 Running（退到安全射击距离
    /// minShootRange + 缓冲，TooCloseCondition 不再成立，Selector 切到射击分支）。
    /// </summary>
    public class KeepDistanceAction : ActionNode
    {
        private readonly EnemyController enemy;
        private readonly EnemyBehavior behavior;

        public KeepDistanceAction(EnemyController enemy, EnemyBehavior behavior)
        {
            this.enemy = enemy;
            this.behavior = behavior;
        }

        public override NodeState Evaluate()
        {
            if (enemy.Player == null) return NodeState.Failure;

            // 远离方向 = 从玩家指向自己
            Vector2 away = (Vector2)enemy.transform.position - (Vector2)enemy.Player.position;
            if (away.sqrMagnitude < 0.0001f) return NodeState.Running; // 完全重合，动不了

            // 目标点：退到离玩家"minShootRange + 缓冲"处（每帧重新算，因为玩家在动）。
            // 缓冲 0.5f：让停点比临界距离略远，避免停在 dist ≈ minShootRange 的临界点，
            // 玩家稍微逼近就又触发后退（TooCloseCondition），造成"退→开火→退"抖动。
            float safeDistance = behavior.minShootRange + 0.5f;
            Vector2 target = (Vector2)enemy.Player.position + away.normalized * safeDistance;
            enemy.MoveTowards(target, behavior.chaseSpeed);
            return NodeState.Running;
        }
    }
}
```

```csharp
using Game.Core;
using Game.Entities;
using Game.Weapons;
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 动作：远程射击玩家。
    ///
    /// 从池取一颗 EnemyProjectile，朝玩家方向发射。
    /// 冷却由节点自己管理（behavior.shootCooldown）。
    ///
    /// 冷却中返回 Running（锁定射击姿态）；发射成功返回 Success。
    /// </summary>
    public class ShootAction : ActionNode
    {
        private readonly EnemyController enemy;
        private readonly EnemyBehavior behavior;
        private readonly ObjectPool projectilePool;
        private float cooldownTimer;

        public ShootAction(EnemyController enemy, EnemyBehavior behavior, ObjectPool projectilePool)
        {
            this.enemy = enemy;
            this.behavior = behavior;
            this.projectilePool = projectilePool;
        }

        public override NodeState Evaluate()
        {
            if (cooldownTimer > 0f)
            {
                cooldownTimer -= Time.deltaTime;
                return NodeState.Running; // 冷却中，保持射击姿态
            }

            if (enemy.Player == null || projectilePool == null) return NodeState.Failure;

            GameObject bulletObj = projectilePool.Get(enemy.transform.position, Quaternion.identity);
            if (bulletObj.TryGetComponent(out EnemyProjectile bullet))
            {
                // 朝向玩家
                Vector2 dir = (Vector2)enemy.Player.position - (Vector2)enemy.transform.position;
                float angle = Mathf.Atan2(dir.y, dir.x) * Mathf.Rad2Deg;

                DamageInfo info = new DamageInfo(behavior.projectileDamage);
                bullet.Launch(enemy.transform.position, Quaternion.Euler(0f, 0f, angle),
                    behavior.projectileSpeed, info);

                cooldownTimer = behavior.shootCooldown;
                return NodeState.Success;
            }
            return NodeState.Failure;
        }
    }
}
```

**`ExplodeAction.cs`** —— 参考实现：`Reference/Scripts/AI/Enemy/ExplodeAction.cs`。

```csharp
using Game.Core;
using Game.Entities;
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 动作：自爆——范围内范围伤害（类似手雷），然后自己死亡。
    ///
    /// 爆炸判定用 Physics2D.OverlapCircle 找玩家（和 Grenade 同一套路）。
    /// 自爆通过 health.TakeDamage(大额) 触发正常死亡流程
    /// （广播 EnemyDiedEvent → DeadState → Room 计数清空）。
    /// </summary>
    public class ExplodeAction : ActionNode
    {
        private const int MaxHits = 16;
        private readonly Collider2D[] hitBuffer = new Collider2D[MaxHits];
        private readonly ContactFilter2D filter = ContactFilter2D.noFilter;

        private readonly EnemyController enemy;
        private readonly EnemyBehavior behavior;

        public ExplodeAction(EnemyController enemy, EnemyBehavior behavior)
        {
            this.enemy = enemy;
            this.behavior = behavior;
        }

        public override NodeState Evaluate()
        {
            if (enemy.Player == null) return NodeState.Failure;

            // 范围伤害：爆炸点 = 敌人自身位置
            int count = Physics2D.OverlapCircle(enemy.transform.position,
                behavior.explodeRange, filter, hitBuffer);
            for (int i = 0; i < count; i++)
            {
                if (!hitBuffer[i].CompareTag("Player")) continue;
                if (hitBuffer[i].TryGetComponent(out Health health))
                    health.TakeDamage(behavior.explodeDamage);
            }

            // 自爆：自己死亡（触发正常死亡流程）
            enemy.health.TakeDamage(int.MaxValue);
            return NodeState.Success;
        }
    }
}
```

```csharp
        /// 远程敌人树：
        ///   被贴脸后退 > 射击（保持距离）> 追击 > 巡逻
        /// </summary>

                    new InSightCondition(enemy, b),

                    new ShootAction(enemy, b, enemyProjectilePool)
                ),

                new SequenceNode(
                    new InSightCondition(enemy, b),
                    new ChaseAction(enemy, b)
                ),
                // 4. 巡逻
                new PatrolAction(enemy, b)
            );
            return new BehaviorTree(blackboard, root);
        }

        /// <summary>
        /// 自爆敌人树：
        ///   进入引爆范围 → 引爆 > 追击（高速冲向玩家）> 巡逻
        /// </summary>
        private BehaviorTree BuildBomberTree(EnemyBehavior b)
        {
            Node root = new SelectorNode(
                // 1. 玩家进入引爆范围 → 轰
                new SequenceNode(
                    new InSightCondition(enemy, b),
                    new InExplodeRangeCondition(enemy, b),
                    new ExplodeAction(enemy, b)
                ),
                // 2. 在视野 → 冲向玩家（用追击速度）
                new SequenceNode(
                    new InSightCondition(enemy, b),
                    new ChaseAction(enemy, b)
                ),
                // 3. 巡逻
                new PatrolAction(enemy, b)
            );
            return new BehaviorTree(blackboard, root);
        }
```

> **注意远程树的分支优先级**：`贴脸后退` 排在 `射击` 前面。因为 Selector 从高到低试——玩家贴脸时"后退"优先；退到安全距离后 TooCloseCondition 不成立 → 落"射击"分支。这就是行为树处理"远近自动调节"的方式，FSM 需要三个状态来回切，行为树只是分支优先级。

```csharp
using Game.Core;
using Game.Entities;
using Game.Weapons;
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 动作：Boss 技能——一次完整的技能释放。
    ///
    /// 两种形态（通过 useProjectile 切换）：
    ///   useProjectile = false → 近战挥击：贴脸范围内直接扣血 + 施加状态异常
    ///   useProjectile = true  → 远程吐息：发射带状态异常的 EnemyProjectile
    ///
    /// 技能参数全部来自 EnemyBehavior 的 Boss 专属字段：
    ///   skillCooldown / skillDamage / skillBurnDuration / skillBurnDamage / skillBurnTickInterval
    ///
    /// 冷却中返回 Running（锁定技能姿态）；释放成功返回 Success。
    /// 这就是"技能系统"的最小形态——一个技能 = 一个 Action 节点 + 参数 + 冷却。
    /// </summary>
    public class BossSkillAction : ActionNode
    {
        private readonly EnemyController enemy;
        private readonly EnemyBehavior behavior;
        private readonly ObjectPool projectilePool;
        private readonly bool useProjectile;
        private float cooldownTimer;

        public BossSkillAction(EnemyController enemy, EnemyBehavior behavior,
            bool useProjectile, ObjectPool projectilePool)
        {
            this.enemy = enemy;
            this.behavior = behavior;
            this.useProjectile = useProjectile;
            this.projectilePool = projectilePool;
        }

        public override NodeState Evaluate()
        {
            // 冷却中：锁定技能姿态
            if (cooldownTimer > 0f)
            {
                cooldownTimer -= Time.deltaTime;
                return NodeState.Running;
            }
            if (enemy.Player == null) return NodeState.Failure;

            // 组装伤害信息：基础伤害 + 灼烧（skillBurn* 配置了才加）
            DamageInfo info = new DamageInfo(behavior.skillDamage);
            if (behavior.skillBurnDuration > 0f && behavior.skillBurnDamage > 0)
            {
                info = info.WithAddedStatus(StatusEffectConfig.Burn(
                    behavior.skillBurnDuration, behavior.skillBurnDamage,
                    behavior.skillBurnTickInterval));
            }

            if (useProjectile)
            {
                // ---- 远程吐息：发射带灼烧的子弹 ----
                if (projectilePool == null) return NodeState.Failure;
                GameObject bulletObj = projectilePool.Get(enemy.transform.position, Quaternion.identity);
                if (!bulletObj.TryGetComponent(out EnemyProjectile bullet)) return NodeState.Failure;

                Vector2 dir = (Vector2)enemy.Player.position - (Vector2)enemy.transform.position;
                float angle = Mathf.Atan2(dir.y, dir.x) * Mathf.Rad2Deg;
                bullet.Launch(enemy.transform.position, Quaternion.Euler(0f, 0f, angle),
                    behavior.projectileSpeed, info);
            }
            else
            {
                // ---- 近战挥击：直接扣血 + 施加灼烧 ----
                if (enemy.Player.TryGetComponent(out Health health))
                {
                    health.TakeDamage(info);
                    if (enemy.Player.TryGetComponent(out StatusEffectManager statusManager))
                        statusManager.ApplyEffects(info);
                }
            }

            cooldownTimer = behavior.skillCooldown;
            return NodeState.Success;
        }
    }
}
```

### 4.3 更新 `EnemyBrain.cs`——补上 Boss 树

参考实现：`Reference/Scripts/Entities/EnemyBrain.cs`。把 BuildBossTree 占位换成真实现。

```csharp
        /// <summary>
        /// Boss 多阶段树：
        ///   阶段2（血<50%，远程吐息带灼烧）> 阶段1（血≥50%，近战挥击带灼烧）
        ///   > 追击 > 巡逻
        ///
        /// 阶段切换完全靠条件（BossPhaseCondition）实时判断，
        /// 不需要重建树——这就是行为树处理"多阶段"的方式：
        ///   阶段 = 树里的一个带血量阈值条件的分支。
        /// </summary>
        private BehaviorTree BuildBossTree(EnemyBehavior b)
        {
            Node root = new SelectorNode(
                // 阶段 2：血量 < 50% → 远程吐息（带灼烧）
                new SequenceNode(
                    new BossPhaseCondition(enemy, 0.5f),
                    new InSightCondition(enemy, b),
                    new BossSkillAction(enemy, b, true, enemyProjectilePool)
                ),
                // 阶段 1：还没到阶段 2（血量 ≥ 50%）→ 近战挥击（带灼烧）
                new SequenceNode(
                    new InverterNode(new BossPhaseCondition(enemy, 0.5f)),
                    new InSightCondition(enemy, b),
                    new BossSkillAction(enemy, b, false, enemyProjectilePool)
                ),
                // 追击
                new SequenceNode(
                    new InSightCondition(enemy, b),
                    new ChaseAction(enemy, b)
                ),
                // 巡逻
                new PatrolAction(enemy, b)
            );
            return new BehaviorTree(blackboard, root);
        }
```

> **Boss 多阶段的本质**：阶段不是独立的系统，而是**树里的分支条件**。`BossPhaseCondition` 用血量比例决定走哪条分支——半血前走"近战挥击"，半血后走"远程吐息"。想加阶段 3？加一个 `BossPhaseCondition(0.25f)` 分支 + 一个新技能节点即可，树结构不变。

## 5. 设计决策记录

### 5.1 为什么行为树和状态机分层，而不是全用行为树

"主动决策"（该干什么）适合行为树——可组合、可换类型。"被动打断"（被打了必须停）不适合行为树——它是**无条件抢占**，行为树表达"打断"很别扭（要每个节点检查是否被击退）。

所以：**行为树管主动，状态机管被动**，用 `IsActionLocked` 协调。击退/死亡时行为树暂停，结束回 FreeState 再继续。这个分层让两种模式各干擅长的事。

### 5.2 为什么用 EnemyBehavior SO 数据驱动，而不是每个类型一个控制器子类

每类型一个子类 = 敌人越多类越多，行为组合靠继承很僵化。SO 数据驱动 = 同一个 EnemyController + 同一个 EnemyBrain，换 behavior 就换行为。新增敌人类型时，如果现有树能满足就只加一个 SO；要新行为才加节点 + 一棵新树。

### 5.3 为什么节点用构造函数注入 EnemyController，黑板只存 enemy 引用

节点是纯逻辑，构造时把 `enemy` + `behavior` 传进去最直白（读数据、调方法都直接用）。黑板是"节点间共享运行时数据"的机制——目前敌人节点各算各的（每个节点自己算距离），暂时用不上共享。黑板保留在框架里（Boss 技能、多 Agent 共享时有用），但敌人节点优先构造注入。

### 5.4 为什么技能 = 一个 Action 节点

`BossSkillAction` 一个节点封装了技能的完整生命周期：冷却（Running 锁定）→ 释放（伤害 + 状态异常）→ 进入冷却。要加新技能 = 写一个新 Action（或参数化现有 Action）+ 在树里加一个分支。技能池 = Selector 里的多个技能分支。这比"技能系统"单独搞一套管理器更轻、更符合行为树范式。

### 5.5 状态类 Patrol/Chase/Attack 现在去哪了

被行为树取代，不再被引用。`EnemyController` 重构后没人 `new` 它们了。Assets 里的这三个文件**留着也不会编译报错**（没人引用，类还在），你可以选择删掉或留着当参考。`EnemyDeadState` 保留（死亡是被动打断）。

## 9. 验收前设计修正（2026-08-10）

> 本节记录首轮静态 review 后确认需要补上的设计调整。它不是“已经验收通过”的完成记录：代码仍由用户在 `Assets/` 中手动修改，修改后还要经过 Unity 编译、Play 验收和回归 review。

### 9.1 设计修正一：恢复视野迟滞，而不是只使用一个探测半径

**对应 review 问题 1**：`EnemyBehaviour` 同时定义了 `detectionRange` 和 `lostSightRange`，但当前 `InSightCondition` 始终只判断：

```csharp
enemy.DistanceToPlayer() <= behaviour.detectionRange
```

这会丢失原 FSM 已经验证过的迟滞设计。敌人在 `detectionRange` 边缘时，玩家只要轻微移动，行为就可能在“巡逻 ↔ 追击”之间反复切换。

正确语义应当是：

- **尚未发现玩家时**：距离小于等于 `detectionRange` 才进入警戒/追击。
- **已经发现玩家后**：允许玩家暂时跑出 `detectionRange`；只有距离大于 `lostSightRange` 才真正丢失目标。
- Inspector 必须保持 `detectionRange < lostSightRange`，两者之间的区间就是防抖缓冲区。

#### 方案选择：感知更新 → Blackboard → 无状态条件节点

首版修正曾考虑“让多个分支共享同一个带 `hasSight` 字段的 `InSightCondition` 实例”。这种办法改动少、能够工作，但它只是最低修正：同一个节点同时挂在多个父节点下面，行为树会从严格的树变成共享节点图；将来节点增加 `Enter`/`Exit`/`Reset` 生命周期或可视化调试时，节点归属会变得含糊。

本项目最终采用更常见的分层方式：

```text
EnemyBrain.FixedUpdate
    → 更新一次敌人感知（距离 + 迟滞）
    → 把结果写进该敌人自己的 Blackboard
    → BehaviourTree.Evaluate
    → 每个 Condition 节点只读取同一份感知快照
```

这里的职责边界是：

- `EnemyBrain`：每个物理帧更新一次感知事实。
- `Blackboard`：保存同一棵树的节点共享数据。
- `InSightCondition` 等条件节点：只读 Blackboard，不自己维护警戒状态。
- `EnemyController`：继续只负责实体数据、移动能力和被动状态打断，不重新塞入具体 AI 决策。

#### 为什么不直接把 `bool`/`float` 每帧写进现有 Blackboard

当前 `Blackboard` 的底层容器是 `Dictionary<string, object>`，`Get<T>` 也只支持 `class`。如果为了存 `bool` 和 `float` 而直接去掉泛型约束，那么这些值类型每次写入 `object` 都会发生装箱；每个敌人每个物理帧写两次，会制造不必要的 GC。

因此这里不改 `Blackboard` API，而是把感知结果收进一个引用类型对象：对象只创建一次、只放入 Blackboard 一次，之后每帧原地更新字段，不产生持续装箱分配。

#### 9.1.1 新建 `Assets/Scripts/AI/Enemy/EnemyPerceptionData.cs`

参考实现应放在 `Reference/Scripts/AI/Enemy/EnemyPerceptionData.cs`，由用户在 `Assets/` 对应路径手动创建：

```csharp
using UnityEngine;

namespace Game.AI
{
    /// <summary>
    /// 单个敌人的感知快照。
    /// EnemyBrain 每个物理帧更新一次，行为树节点只读取。
    /// 这是引用类型：放入 Blackboard 后反复修改字段，不产生值类型装箱 GC。
    /// </summary>
    public sealed class EnemyPerceptionData
    {
        public Transform Target { get; set; }
        public float DistanceToTarget { get; set; } = float.MaxValue;
        public bool IsAlerted { get; set; }
    }
}
```

#### 9.1.2 新建 `Assets/Scripts/AI/Enemy/EnemyBlackboardKeys.cs`

参考实现应放在 `Reference/Scripts/AI/Enemy/EnemyBlackboardKeys.cs`：

```csharp
namespace Game.AI
{
    /// <summary>
    /// 敌人行为树使用的 Blackboard 键名。
    /// 集中定义，避免不同节点手写字符串产生静默拼写错误。
    /// </summary>
```

#### 9.1.3 更新 `EnemyBrain`：每个物理帧只更新一次感知

在字段区增加：

```csharp
private EnemyPerceptionData perception;
```

`Awake` 中创建 Blackboard 后，创建感知对象并只登记一次：

```csharp
private void Awake()
{
    enemy = GetComponent<EnemyController>();

    blackboard = new Blackboard();
    blackboard.Set("enemy", enemy);

    perception = new EnemyPerceptionData();
    blackboard.Set(EnemyBlackboardKeys.Perception, perception);
}
```

`FixedUpdate` 必须先更新感知，再评估行为树：

```csharp
private void FixedUpdate()
{
    if (enemy.IsActionLocked) return;

    UpdatePerception();
    tree.Evaluate();
}
```

新增感知更新方法：

```csharp
private void UpdatePerception()
{
    perception.Target = enemy.Player;

    if (perception.Target == null)
    {
        perception.DistanceToTarget = float.MaxValue;
        perception.IsAlerted = false;
        return;
    }

    float distance = enemy.DistanceToPlayer();
    perception.DistanceToTarget = distance;

    if (!perception.IsAlerted && distance <= enemy.Behaviour.detectionRange)
        perception.IsAlerted = true;
    else if (perception.IsAlerted && distance > enemy.Behaviour.lostSightRange)
        perception.IsAlerted = false;
}
```

注意：Blackboard 是**每个 `EnemyBrain` 各自 `new` 的一份**，所以每个敌人都有独立的 `EnemyPerceptionData`，不会出现一只敌人发现玩家、全房间敌人同时警戒的情况。以后如果要做敌群协同，再另外显式引入共享黑板，而不是偷偷把当前黑板改成全局静态对象。

#### 9.1.4 更新 `InSightCondition`：变成无状态读取节点

参考实现应更新到 `Reference/Scripts/AI/Enemy/InSightCondition.cs`：

```csharp
namespace Game.AI
{
    /// <summary>
    /// 条件：本敌人的感知系统当前是否仍处于警戒状态。
    /// 迟滞计算由 EnemyBrain 统一完成，本节点只读取结果。
    /// </summary>
    public class InSightCondition : ConditionNode
    {
        private readonly EnemyPerceptionData perception;

        public InSightCondition(Blackboard blackboard)
        {
            perception = blackboard.Get<EnemyPerceptionData>(
                EnemyBlackboardKeys.Perception);
        }

        protected override bool Check()
        {
            return perception != null && perception.IsAlerted;
        }
    }
}
```

现在每个分支可以拥有自己的 `InSightCondition` 实例；这些节点本身没有状态，只是读取同一份 `EnemyPerceptionData`。

统一替换为：

#### 9.1.6 后续扩展方向（本次不必一起做）

`EnemyPerceptionData.DistanceToTarget` 已经是本物理帧统一计算出的距离快照。后续可以让 `InAttackRangeCondition`、`InShootRangeCondition`、`TooCloseCondition`、`InExplodeRangeCondition` 也读取它，避免同一棵树在一帧内多次调用 `Vector2.Distance`。

这不是本次恢复迟滞的必要条件，建议先只改 `InSightCondition`，完成 Play 验收后再做，避免一次改动范围过大。未来还可以继续加入：

- `LastKnownTargetPosition`：玩家离开视野后，敌人先去最后位置搜索。
- `LastSeenTime`：丢失目标后保留数秒警戒。
- `HasLineOfSight`：加入墙体射线检测后，区分“距离内”和“真的看得见”。
- `SelectedSkill` / `CurrentPhase`：给复杂 Boss 节点共享技能决策。

#### Play 验收

1. 让玩家停在 `detectionRange` 外：敌人继续巡逻。
2. 进入 `detectionRange`：敌人开始追击。
3. 退到 `detectionRange` 与 `lostSightRange` 之间：敌人继续追击，不应立刻巡逻。
4. 继续退到 `lostSightRange` 外：敌人才恢复巡逻。
5. 在 `detectionRange` 边缘来回小幅移动：不得出现快速状态抖动。
6. 分别检查近战、远程、自爆和 Boss，因为四棵树都要从自己的 Blackboard 读取感知结果。
7. 同时摆放两只敌人，只让玩家靠近其中一只：另一只不应因为前者进入警戒而同步追击，证明 Blackboard 没有被错误做成全局共享。
8. 敌人被击退后跑出 `lostSightRange`：击退结束的下一次行为树评估应先刷新感知，然后恢复巡逻，而不是继续追向玩家。

### 9.2 设计修正二：Boss 阶段阈值必须来自 `EnemyBehaviour.phaseThresholds`

**对应 review 问题 4**：`EnemyBehaviour` 已经暴露 `phaseThresholds`，但当前 `EnemyBrain.BuildBossTree` 仍写死两次 `0.5f`：

```csharp
new BossPhaseCondition(enemy, 0.5f)
```

这会造成两个问题：

1. 修改 `BossBehavior` 资产中的阶段阈值不会改变游戏行为，数据驱动名存实亡。
2. `phaseThresholds` 声称可以支持多个阶段，但节点只接收裸数值，数组索引与行为树分支之间没有明确对应关系。

不能只把代码机械地改成 `b.phaseThresholds[0]`：当前资产可能是空数组，直接读取会抛出 `IndexOutOfRangeException`。正式方案是让 `BossPhaseCondition` 接收“行为档案 + 阶段编号”，由条件节点把阶段编号换算成完整血量区间；`EnemyBrain` 则在建树时集中检查一次数组是否合法。

这里的参数使用符合人类直觉的**一基编号**：`1` 表示阶段 1，`2` 表示阶段 2。调用者不需要知道“阶段 2 对应阈值数组索引 0”这样的内部换算关系。

#### 9.2.1 明确 `phaseThresholds` 的数据契约

- 每个元素代表一次“进入下一阶段”的血量比例。
- 阈值必须位于 `0` 和 `1` 之间。
- 多个阈值必须从高到低排列。
- `[0.5]` 表示两阶段：血量低于 50% 进入阶段 2。
- `[0.7, 0.3]` 表示三阶段：低于 70% 进入阶段 2，低于 30% 进入阶段 3。

为避免相邻阶段在阈值点重叠，区间统一定义为“下界包含、上界不包含”，第一阶段额外包含血量上限 `1`：

```text
[0.5]      → 阶段 1 = [0.5, 1]，阶段 2 = [0, 0.5)
[0.7, 0.3] → 阶段 1 = [0.7, 1]，阶段 2 = [0.3, 0.7)，阶段 3 = [0, 0.3)
```

因此血量恰好等于 `0.5` 时仍处于阶段 1，只有低于 `0.5` 才进入阶段 2，与原本的 `< threshold` 语义一致。

数组长度并不会自动生成新的技能分支。`phaseThresholds.Length + 1` 只是可表达的阶段数；每个阶段仍需在 `BuildBossTree` 中有对应分支。这一点修正了前文“改数组就得到三阶段”的过度简化描述。

#### 9.2.2 更新 `BossPhaseCondition`

目标文件：`Assets/Scripts/AI/BossPhaseCondition.cs`<br>
参考实现：`Reference/Scripts/AI/BossPhaseCondition.cs`

构造函数改为接收一基的阶段编号：

```csharp
public BossPhaseCondition(
    EnemyController enemy,
    EnemyBehaviour behaviour,
    int phaseNumber)
```

阶段序列已经由 `EnemyBrain` 在建树前统一校验，因此条件节点不再每帧重复校验数组。构造时把阶段编号换算成上下界并缓存：

```csharp
public BossPhaseCondition(
    EnemyController enemy,
    EnemyBehaviour behaviour,
    int phaseNumber)
{
    this.enemy = enemy;

    float[] thresholds = behaviour.phaseThresholds;
    if (phaseNumber < 1 || phaseNumber > thresholds.Length + 1)
        throw new ArgumentOutOfRangeException(nameof(phaseNumber));

    upperBound = phaseNumber == 1
        ? 1f
        : thresholds[phaseNumber - 2];

    lowerBound = phaseNumber == thresholds.Length + 1
        ? 0f
        : thresholds[phaseNumber - 1];

    includeUpperBound = phaseNumber == 1;
}

protected override bool Check()
{
    if (enemy.health == null || enemy.health.Max <= 0) return false;

    float healthRatio = (float)enemy.health.Current / enemy.health.Max;
    bool belowUpperBound = includeUpperBound
        ? healthRatio <= upperBound
        : healthRatio < upperBound;

    return healthRatio >= lowerBound && belowUpperBound;
}
```

这样 `Check()` 只负责读取动态血量。错误的阶段编号属于建树代码错误，会在构造时立即暴露；SO 阈值配置错误则由 `EnemyBrain` 在构造节点之前拦截。

#### 9.2.3 更新 `EnemyBrain.BuildBossTree`

目标文件：`Assets/Scripts/Entities/EnemyBrain.cs`<br>
参考实现：`Reference/Scripts/Entities/EnemyBrain.cs`

当前 Boss 只有两个阶段，所以分支直接写“阶段 2”和“阶段 1”。阶段 1 不再通过 `Inverter(阶段 2)` 间接表达：

```csharp
private BehaviourTree BuildBossTree(EnemyBehaviour b)
{
    if (!ValidateBossPhaseThresholds(b, 2))
        return null;

    Node root = new SelectorNode(
        new SequenceNode(
            new BossPhaseCondition(enemy, b, 2),
            new InSightCondition(blackboard),
            new BossSkillAction(enemy, b, true, enemyProjectilePool)
        ),
        new SequenceNode(
            new BossPhaseCondition(enemy, b, 1),
            new InSightCondition(blackboard),
            new InAttackRangeCondition(enemy, b),
            new BossSkillAction(enemy, b, false, enemyProjectilePool)
        ),
        new SequenceNode(
            new InSightCondition(blackboard),
            new ChaseAction(enemy, b)
        ),
        new PatrolAction(enemy, b)
    );

    return new BehaviourTree(blackboard, root);
}
```

完整参考版还包含 `ValidateBossPhaseThresholds`：它只在建树时检查一次数组长度、数值范围和降序关系。当前树只实现两个阶段，因此明确要求 `phaseThresholds.Length == 1`；将来真正增加第三阶段分支时，再把预期阶段数改成 `3`。

若校验失败，`BuildBossTree` 返回 `null`；`Start` 会禁用 `EnemyBrain`，避免在 `FixedUpdate` 中评估空树：

```csharp
tree = BuildTree(enemy.Behaviour);
if (tree == null)
    enabled = false;
```

#### 9.2.4 Unity Inspector 调整

在 `Assets/Data/BossBehavior.asset` 的 `Phase Thresholds` 中设置：

1. `Size = 1`
2. `Element 0 = 0.5`

之后可以把 `Element 0` 改成 `0.7` 做验证：Boss 应在血量低于 70% 时切换，而不是继续固定在半血切换。验证后再改回最终希望使用的数值。

#### 三阶段扩展规则

若以后使用 `[0.7, 0.3]`，建树代码可以直接使用阶段编号：

```text
BossPhaseCondition(enemy, b, 3) → 阶段 3 技能分支
BossPhaseCondition(enemy, b, 2) → 阶段 2 技能分支
BossPhaseCondition(enemy, b, 1) → 阶段 1 技能分支
追击
巡逻
```

三个条件判断的是互不重叠的完整区间，因此 20% 血量只会满足阶段 3，不会同时满足阶段 2。仍建议按“阶段 3 → 2 → 1”排列，让树的阅读顺序与技能优先级一目了然，但正确性不再依赖 Selector 的排列顺序。
