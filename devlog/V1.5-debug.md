# V1.5 统一调试系统：分类日志、统一开关与屏幕面板

> 这次的主题是**让调试输出也有自己的架构边界**：业务代码只说明“哪个模块发生了什么”，统一入口负责分类、过滤，并决定消息去 Unity Console、游戏内屏幕，还是两边都去。
>
> 照旧：分 4 步推进。由于新命名空间 `Game.Debug` 会暂时遮蔽旧业务代码里的 `UnityEngine.Debug`，**步骤 1 与步骤 2 合起来才是第一个可编译单元**；步骤 3、4 再分别做 Play 验收。五个新脚本在本文给完整代码；四个已有脚本只列出需要修改的明确单元。九个文件的完整当前版本都保存在 `Reference/Scripts/...`，由你自己同步到 `Assets/Scripts/...`。Unity 场景和 ScriptableObject 仍由你在编辑器里亲手配置。
>
> 日期：2026-08-16～2026-08-19。当前状态：**四个步骤均已完成，静态检查与 Unity Play 验收通过；`V1.5-debug` 正式收口。**

## 本轮目标

- **统一入口**：业务代码统一调用 `GameDebug.Log/Warning/Error`，不再直接使用 `Debug.Log*`。
- **分类过滤**：按 `System`、`Input`、`Combat`、`AI`、`Level`、`Pool` 六类开关消息。
- **集中配置**：用一份 `DebugSettings` ScriptableObject 控制总开关、输出目标和高开销诊断。
- **双路输出**：同一条消息可转发到 Unity Console 与游戏内 `DebugOverlay`。
- **调试 UI 收口**：新面板接管旧 `DebugText` 的输入缓冲显示，不再保留第二套 `display` 开关。

完成后：发布前只关闭一个总开关；排查程序化关卡时可以只看 `Level` 日志；最大化 Game 视图或运行 Development Build 时，也能直接看到最近消息。现有玩法逻辑保持不变。

---

## 0. 先理解：为什么要统一调试输出

项目当前只有少量日志，但已经出现三种互不统一的调试方式：

- `EnemyBrain`、`StatusEffectManager`、`LevelManager` 直接调用 `Debug.Log`；
- `ObjectPool` 自己维护 `debugMode`，发布前需要单独记得关闭；
- `DebugText` 自己维护 `display`，只显示输入缓冲，不认识其他日志。

如果继续让每个新系统各自增加开关，进入程序化关卡生成后会很快出现这些问题：

1. 想只看关卡生成日志时，AI、战斗和对象池消息仍混在一起；
2. 发布前要去多个组件逐一关闭调试选项，容易遗漏；
3. Build 中没有 Unity Console 时，关键运行信息无法直接在游戏画面里看到；
4. 同一条消息要手写前缀、选择输出目标，格式会越来越不一致。

本轮不是为了“多打日志”，而是先规定以后日志应该从哪里走。程序化关卡生成会涉及种子、图结构、房间放置失败与规则回退，先建立统一入口能明显降低后续诊断成本。

### 0.1 最终结构

本轮新增五个调试脚本：

```text
Assets/Scripts/Debug/
├── DebugCategory.cs   # 分类、严重程度和消息数据
├── DebugSettings.cs   # ScriptableObject 全局设置
├── GameDebug.cs       # 唯一日志入口与消息转发
├── DebugBootstrap.cs  # 在其他 Awake 前注入设置
└── DebugOverlay.cs    # 屏幕日志 + 输入缓冲显示
```

完整参考实现位于：

- `Reference/Scripts/Debug/DebugCategory.cs`
- `Reference/Scripts/Debug/DebugSettings.cs`
- `Reference/Scripts/Debug/GameDebug.cs`
- `Reference/Scripts/Debug/DebugBootstrap.cs`
- `Reference/Scripts/Debug/DebugOverlay.cs`

旧的 `Assets/Scripts/Debug/DebugText.cs` 会由 `DebugOverlay` 替代。新面板继续显示输入缓冲，同时增加最近日志显示，因此不再保留第二套 `display` 开关。

### 0.2 消息流

```text
业务代码
  │
  │ GameDebug.Log / Warning / Error
  ▼
GameDebug
  ├── DebugSettings：总开关 + 分类过滤
  ├── Unity Console
  └── MessagePublished + 最近消息缓存
                    │
                    ▼
               DebugOverlay
               ├── 最近日志
               └── InputBuffer 状态
```

这里没有使用 `EventBus`。调试消息不是游戏玩法事件，也不应该进入正式业务事件表；`GameDebug` 自己的静态事件只服务调试面板。

### 0.3 分类使用 Flags 枚举

当前分类如下：

| 分类 | 用途 |
|---|---|
| `System` | 启动、全局生命周期和无法归入业务模块的信息 |
| `Input` | 输入读取、命令和输入缓冲 |
| `Combat` | 伤害、状态异常、武器和战斗反馈 |
| `AI` | 感知、行为树、敌人配置和 Boss 阶段 |
| `Level` | 房间、门、关卡流程和后续程序化生成 |
| `Pool` | 对象池扩容、重复归还和泄漏诊断 |

`DebugCategory` 带 `[Flags]`，因此 `DebugSettings` 的 Inspector 字段可以同时勾选多个分类。后续新增模块时，在枚举中增加一个位即可；不要改回字符串分类。

### 0.4 三种严重程度

- `GameDebug.Log`：正常的开发期信息；
- `GameDebug.Warning`：程序可以继续运行，但配置或状态值得检查；
- `GameDebug.Error`：当前功能无法正确继续，例如 Boss 阶段配置非法。

传入 `context` 后，点击 Unity Console 中的消息可以定位到对应组件。只要调用位置有合适的 `MonoBehaviour`，建议把 `this` 作为第三个参数传入。

### 0.5 一个 ScriptableObject 管所有开关

`DebugSettings` 提供：

- `Debug Enabled`：总开关；
- `Expensive Checks Enabled`：对象池 `HashSet` 等有额外成本的诊断逻辑；
- `Console Enabled`：是否写入 Unity Console；
- `Overlay Enabled`：是否转发给屏幕面板；
- `Enabled Categories`：分类过滤；
- `Overlay Message Limit`：屏幕保留的最近消息数；
- `Include Timestamp`：是否显示基于 `Time.unscaledTime` 的时间戳。

发布构建前只需要关闭 `Debug Enabled`，不再到 `ObjectPool` 和 UI 组件上寻找独立开关。

### 0.6 为什么需要 DebugBootstrap

对象池会在 `Awake` 中决定是否启用额外诊断。如果设置尚未注入，它无法知道全局开关状态。

`DebugBootstrap` 使用：

```csharp
[DefaultExecutionOrder(-10000)]
```

它会早于普通业务组件运行。这个执行顺序直接写在脚本上，不需要再到 `Project Settings > Script Execution Order` 手动配置。

### 0.7 为什么 GameDebug 自己缓存最近消息

Canvas 上的 `DebugOverlay.OnEnable` 可能晚于某些组件的 `Awake`。如果只订阅实时事件，面板会漏掉启动阶段日志。

因此 `GameDebug` 保存一个有上限的队列：

- 新面板启用时先复制历史；
- 后续消息再通过 `MessagePublished` 实时追加；
- 队列长度始终受 `Overlay Message Limit` 限制，不会无限增长。

### 0.8 为什么保留 Console，同时做屏幕面板

两者解决的问题不同：

- Console 适合查看完整调用栈、点击 `context` 定位对象；
- 屏幕面板适合在最大化 Game 视图或 Development Build 中观察流程。

屏幕面板不是 Console 的替代品。错误排查仍应优先看 Console。

### 1.1 新建 `Assets/Scripts/Debug/DebugCategory.cs`

目标文件：`Assets/Scripts/Debug/DebugCategory.cs`  
参考实现：`Reference/Scripts/Debug/DebugCategory.cs`

```csharp
using System;

namespace Game.Debug
{
    /// <summary>调试消息所属的功能模块，可在 DebugSettings 中按位开关。</summary>
    [Flags]
    public enum DebugCategory
    {
        None = 0,
        System = 1 << 0,
        Input = 1 << 1,
        Combat = 1 << 2,
        AI = 1 << 3,
        Level = 1 << 4,
        Pool = 1 << 5,
        All = System | Input | Combat | AI | Level | Pool,
    }

    /// <summary>调试消息的严重程度。</summary>
    public enum DebugSeverity
    {
        Info,
        Warning,
        Error,
    }

    /// <summary>在 Console 与屏幕调试面板之间传递的一条不可变消息。</summary>
    public readonly struct DebugMessage
    {
        public readonly float Timestamp;
        public readonly DebugCategory Category;
        public readonly DebugSeverity Severity;
        public readonly string Text;

        public DebugMessage(
            float timestamp,
            DebugCategory category,
            DebugSeverity severity,
            string text)
        {
            Timestamp = timestamp;
            Category = category;
            Severity = severity;
            Text = text;
        }

        /// <summary>按统一格式生成可显示文本。</summary>
        public string Format(bool includeTimestamp)
        {
            string prefix = $"[{Category}][{Severity}]";
            return includeTimestamp
                ? $"[{Timestamp:F2}]{prefix} {Text}"
                : $"{prefix} {Text}";
        }
    }
}
```

`DebugCategory` 使用 `[Flags]`，一份设置可以同时启用多个模块；`DebugMessage` 是 Console 与屏幕面板共用的不可变消息数据。

### 1.2 新建 `Assets/Scripts/Debug/DebugSettings.cs`

目标文件：`Assets/Scripts/Debug/DebugSettings.cs`  
参考实现：`Reference/Scripts/Debug/DebugSettings.cs`

```csharp
using UnityEngine;

namespace Game.Debug
{
    /// <summary>统一保存项目调试输出、分类过滤和屏幕面板设置。</summary>
    [CreateAssetMenu(fileName = "DebugSettings", menuName = "Game/Debug Settings")]
    public sealed class DebugSettings : ScriptableObject
    {
        [Header("总开关")]
        [Tooltip("关闭后，GameDebug 不再向 Console 或屏幕面板输出消息。")]
        [SerializeField] private bool debugEnabled = true;

        [Tooltip("启用需要额外集合或检查步骤的诊断逻辑，例如对象池重复归还检测。")]
        [SerializeField] private bool expensiveChecksEnabled = true;

        [Header("输出目标")]
        [SerializeField] private bool consoleEnabled = true;
        [SerializeField] private bool overlayEnabled = true;

        [Header("过滤与格式")]
        [Tooltip("只输出勾选分类的消息。")]
        [SerializeField] private DebugCategory enabledCategories = DebugCategory.All;

        [Tooltip("屏幕面板保留的最近消息数。")]
        [Min(1)]
        [SerializeField] private int overlayMessageLimit = 12;

        [SerializeField] private bool includeTimestamp = true;

        public bool DebugEnabled => debugEnabled;
        public bool ExpensiveChecksEnabled => expensiveChecksEnabled;
        public bool ConsoleEnabled => consoleEnabled;
        public bool OverlayEnabled => overlayEnabled;
        public DebugCategory EnabledCategories => enabledCategories;
        public int OverlayMessageLimit => Mathf.Max(1, overlayMessageLimit);
        public bool IncludeTimestamp => includeTimestamp;
    }
}
```

所有开关都进入同一份 ScriptableObject。以后发布前只需要关闭 `Debug Enabled`，不用再去各个对象池和 UI 组件里逐个找开关。

### 1.3 新建 `Assets/Scripts/Debug/GameDebug.cs`

目标文件：`Assets/Scripts/Debug/GameDebug.cs`  
参考实现：`Reference/Scripts/Debug/GameDebug.cs`

```csharp
using System;
using System.Collections.Generic;
using UnityEngine;
using Object = UnityEngine.Object;

namespace Game.Debug
{
    /// <summary>
    /// 项目唯一的调试消息入口，负责分类过滤并把消息同时转发到 Console 和屏幕面板。
    /// </summary>
    public static class GameDebug
    {
        private static readonly Queue<DebugMessage> overlayHistory =
            new Queue<DebugMessage>();

        private static DebugSettings settings;

        /// <summary>屏幕调试面板订阅的消息事件。</summary>
        public static event Action<DebugMessage> MessagePublished;

        public static DebugSettings Settings => settings;

        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
        private static void ResetStatics()
        {
            settings = null;
            overlayHistory.Clear();
            MessagePublished = null;
        }

        /// <summary>由 DebugBootstrap 在其他游戏逻辑运行前注入设置。</summary>
        public static void Initialize(DebugSettings newSettings)
        {
            settings = newSettings;
            overlayHistory.Clear();

            if (settings == null)
            {
                UnityEngine.Debug.LogError(
                    "[Debug][Error] DebugBootstrap 没有指定 DebugSettings。统一调试输出已停用。");
            }
        }

        /// <summary>当前分类是否允许输出。</summary>
        public static bool IsEnabled(DebugCategory category)
        {
            return settings != null
                && settings.DebugEnabled
                && category != DebugCategory.None
                && (settings.EnabledCategories & category) != 0;
        }

        /// <summary>当前分类是否允许执行有额外开销的诊断检查。</summary>
        public static bool AreExpensiveChecksEnabled(DebugCategory category)
        {
            return IsEnabled(category) && settings.ExpensiveChecksEnabled;
        }

        public static void Log(
            DebugCategory category,
            string message,
            Object context = null)
        {
            Publish(category, DebugSeverity.Info, message, context);
        }

        public static void Warning(
            DebugCategory category,
            string message,
            Object context = null)
        {
            Publish(category, DebugSeverity.Warning, message, context);
        }

        public static void Error(
            DebugCategory category,
            string message,
            Object context = null)
        {
            Publish(category, DebugSeverity.Error, message, context);
        }

        /// <summary>把本次 Play 已缓存的屏幕消息复制给刚启用的面板。</summary>
        public static void CopyOverlayHistory(List<DebugMessage> destination)
        {
            if (destination == null) return;
            destination.Clear();
            destination.AddRange(overlayHistory);
        }

        private static void Publish(
            DebugCategory category,
            DebugSeverity severity,
            string message,
            Object context)
        {
            if (!IsEnabled(category)) return;

            DebugMessage debugMessage = new DebugMessage(
                Time.unscaledTime,
                category,
                severity,
                message);

            if (settings.ConsoleEnabled)
            {
                string formatted = debugMessage.Format(settings.IncludeTimestamp);
                switch (severity)
                {
                    case DebugSeverity.Info:
                        UnityEngine.Debug.Log(formatted, context);
                        break;
                    case DebugSeverity.Warning:
                        UnityEngine.Debug.LogWarning(formatted, context);
                        break;
                    case DebugSeverity.Error:
                        UnityEngine.Debug.LogError(formatted, context);
                        break;
                }
            }

            if (!settings.OverlayEnabled) return;

            overlayHistory.Enqueue(debugMessage);
            while (overlayHistory.Count > settings.OverlayMessageLimit)
                overlayHistory.Dequeue();

            MessagePublished?.Invoke(debugMessage);
        }
    }
}
```

`GameDebug` 是业务代码唯一允许调用的日志入口。它先按分类过滤，再分别转发到 Unity Console 和屏幕面板；缓存队列有固定上限，不会无限增长。

### 1.5 新建 `Assets/Scripts/Debug/DebugOverlay.cs`

目标文件：`Assets/Scripts/Debug/DebugOverlay.cs`  
参考实现：`Reference/Scripts/Debug/DebugOverlay.cs`

```csharp
using System.Collections.Generic;
using System.Text;
using Game.Commands;
using TMPro;
using UnityEngine;

namespace Game.Debug
{
    /// <summary>
    /// 显示 GameDebug 的最近消息，并接管旧 DebugText 的输入缓冲观察功能。
    /// </summary>
    public sealed class DebugOverlay : MonoBehaviour
    {
        [Header("日志")]
        [SerializeField] private TMP_Text logText;

        [Header("输入缓冲")]
        [SerializeField] private TMP_Text inputBufferText;
        [SerializeField] private PlayerInputHandler playerInputHandler;

        private readonly List<DebugMessage> messages = new List<DebugMessage>();
        private readonly StringBuilder builder = new StringBuilder(512);

        private int lastBufferCount = int.MinValue;
        private string lastCommandName;
        private bool lastOverlayVisible;

        private void OnEnable()
        {
            GameDebug.MessagePublished += OnMessagePublished;
            GameDebug.CopyOverlayHistory(messages);
            lastOverlayVisible = IsOverlayVisible();
            RefreshLogText();
            RefreshInputBuffer(true);
            GameDebug.Log(DebugCategory.System, "Debug 面板已启用。", this);
        }

        private void OnDisable()
        {
            GameDebug.MessagePublished -= OnMessagePublished;
        }

        private void Update()
        {
            bool overlayVisible = IsOverlayVisible();
            if (overlayVisible != lastOverlayVisible)
            {
                lastOverlayVisible = overlayVisible;
                RefreshLogText();
                RefreshInputBuffer(true);
            }
            RefreshInputBuffer(false);
        }

        private void OnMessagePublished(DebugMessage message)
        {
            messages.Add(message);

            DebugSettings settings = GameDebug.Settings;
            int limit = settings != null ? settings.OverlayMessageLimit : 1;
            int overflow = messages.Count - limit;
            if (overflow > 0)
                messages.RemoveRange(0, overflow);

            RefreshLogText();
        }

        private void RefreshLogText()
        {
            if (logText == null) return;

            DebugSettings settings = GameDebug.Settings;
            if (settings == null || !settings.DebugEnabled || !settings.OverlayEnabled)
            {
                logText.text = string.Empty;
                return;
            }

            builder.Clear();
            for (int i = 0; i < messages.Count; i++)
            {
                if (i > 0) builder.AppendLine();
                builder.Append(messages[i].Format(settings.IncludeTimestamp));
            }
            logText.text = builder.ToString();
        }

        private void RefreshInputBuffer(bool force)
        {
            if (inputBufferText == null) return;

            DebugSettings settings = GameDebug.Settings;
            if (settings == null
                || !settings.DebugEnabled
                || !settings.OverlayEnabled
                || !GameDebug.IsEnabled(DebugCategory.Input)
                || playerInputHandler == null
                || playerInputHandler.Buffer == null)
            {
                if (force || inputBufferText.text.Length > 0)
                    inputBufferText.text = string.Empty;
                lastBufferCount = int.MinValue;
                lastCommandName = null;
                return;
            }

            InputBuffer buffer = playerInputHandler.Buffer;
            int count = buffer.Count;
            string commandName = buffer.Empty()
                ? "—"
                : buffer.Peek().GetType().Name;

            if (!force && count == lastBufferCount && commandName == lastCommandName)
                return;

            lastBufferCount = count;
            lastCommandName = commandName;
            inputBufferText.text = $"Buffer({count}): {commandName}";
        }

        private static bool IsOverlayVisible()
        {
            DebugSettings settings = GameDebug.Settings;
            return settings != null
                && settings.DebugEnabled
                && settings.OverlayEnabled;
        }
    }
}
```

`DebugOverlay` 同时承担最近日志显示与旧 `DebugText` 的输入缓冲观察职责。日志只在收到新消息或开关变化时重建；输入缓冲文本也会缓存上一次结果，避免无意义地每帧改 TMP 文本。

### ✅ 步骤 1 验收

此时先不要删除旧 `DebugText.cs`，也不要创建设置资产。先确认五个新脚本和对应 `.meta` 都已生成。

### 2.1 更新 `Assets/Scripts/Core/ObjectPool.cs`

变化：

- 删除每个对象池自己的 `debugMode` 字段；
- `Awake` 通过 `GameDebug.AreExpensiveChecksEnabled(DebugCategory.Pool)` 缓存本次运行是否启用诊断；
- 重复 `Release` 改用 `GameDebug.Error(DebugCategory.Pool, ...)`；
- `inPool` 仍只在诊断启用时维护，关闭全局调试后不会承担这部分运行成本。

注意：`diagnosticsEnabled` 在对象池 `Awake` 时确定。不要在 Play 中途切换 `Expensive Checks Enabled` 来测试它；修改后停止并重新进入 Play。

private bool ValidateBossPhaseThresholds(EnemyBehaviour behaviour, int expectedPhaseCount)
{
    float[] thresholds = behaviour.phaseThresholds;
    if (thresholds == null || thresholds.Length != expectedPhaseCount - 1)
    {
        GameDebug.Error(
            DebugCategory.AI,
            $"当前 Boss 树需要 {expectedPhaseCount - 1} 个阶段阈值。",
            this);

    }

    float previous = 1f;
    for (int i = 0; i < thresholds.Length; i++)

                this);
            return false;
        }
        previous = current;
    }
    return true;
}

| 字段 | 建议值 | 含义 |
|---|---:|---|
| Anchor Min | `X = 0, Y = 1` | 锚定到 Canvas 左上角 |

| Height | `320` | 面板高度 |
| Scale | `X = 1, Y = 1, Z = 1` | 避免继承到意外缩放 |

最快的锚点设置方法是点击 `Rect Transform` 左上角的 Anchor Presets 小方块，然后选择“左上角”。如果点击后位置发生变化，再按照上表手动填写 `Pos X`、`Pos Y`、`Width` 和 `Height` 即可。

| 字段 | 建议值 |

| Source Image | `None (Sprite)` |

4. 如果想保留这个 TMP 物体作其他用途，则点击 `Debug Text (Script)` 组件右上角菜单，选择 `Remove Component`，并把物体改成不会与新面板混淆的名字；
5. `Ctrl+S` 保存 `SampleScene`。

“删除整个旧物体”和“只移除脚本组件”二选一，不需要两个都做。关键是保存后的场景里不再存在 `DebugText` 组件。

可以在 Hierarchy 搜索框输入 `t:DebugText` 做一次确认：结果应为空。若还有结果，逐个检查是遗漏的场景对象还是你后来新增的引用；不要急着删除脚本文件。

#### 4.3.2 再删除旧脚本资产

1. 在 Project 窗口进入 `Assets/Scripts/Debug/`；
2. 选中旧的 `DebugText.cs`，不要选到新建的 `DebugOverlay.cs`；
3. 右键选择 `Delete`，确认删除；
4. 从 Unity 的 Project 窗口删除即可，**不要再去文件管理器单独处理 `.meta`**；Unity 会同步删除对应 `.meta` 并刷新资产数据库；
5. 等待右下角编译进度结束；
6. Console 应保持 0 error / 0 warning；
7. 再次选中 `UI > DebugOverlay`，确认三个序列化引用没有变成 `None`；
8. `Ctrl+S` 再保存一次场景。

#### 4.3.3 最后确认没有 Missing Script

再次进入 Play，确认：

- Hierarchy 中只剩新 `UI > DebugOverlay`，旧 `UI > Debug` 已删除或不再挂 `DebugText`；
- Inspector 没有显示 `Missing (Mono Script)`；
- 输入缓冲文字仍正常变化；
- 屏幕日志仍能显示；
- Console 没有因为删除旧脚本产生新的错误。

不要在新面板验证之前先删除旧脚本，否则输入缓冲显示出问题时会失去可工作的对照，也更难判断是布局、引用还是脚本本身出了问题。

### ✅ 步骤 4 验收

- 按下 `Shift` 或 `Q`，在动作暂时不可执行时能看到缓冲数量与命令名；
- 条件满足或命令过期后，显示回到 `Buffer(0): —`；
- `Console Enabled = false`、`Overlay Enabled = true` 时，统一日志只出现在画面；
- `Console Enabled = true`、`Overlay Enabled = false` 时，统一日志只出现在 Console；
- `Debug Enabled = false` 时，两处都不显示，输入缓冲文本也清空；
- 反复禁用/启用 `DebugOverlay` GameObject，不出现重复日志，验证订阅与退订成对。

## 今后如何写日志

普通信息：

```csharp
GameDebug.Log(DebugCategory.Level, $"生成完成，Seed={seed}。", this);
```

可恢复的异常：

```csharp
GameDebug.Warning(DebugCategory.Level, "宝箱房放置失败，已回退为普通房。", this);
```

当前功能无法继续：

```csharp
GameDebug.Error(DebugCategory.Level, "没有可用的起始房配置。", this);
```

调用脚本需要：

```csharp
using Game.Debug;
```

### 不应该写日志的情况

- 不要在 `Update`、`FixedUpdate` 或行为树每次 `Evaluate` 中无条件打印；
- 不要用日志代替游戏事件或状态变化；
- 不要记录玩家隐私、账号令牌、文件系统敏感路径；
- 不要为每次子弹移动、每次 DoT 倒计时打印消息；
- 不要在业务代码里重新拼 `[LevelManager]` 一类前缀，分类与格式由 `GameDebug` 统一生成。

如果某条高频日志只在特殊排查时需要，应先在状态发生变化的边缘输出，而不是每帧输出。例如只记录“进入警戒”和“退出警戒”，不要每帧记录距离。

## 常见问题排查

| 现象 | 优先检查 |
|---|---|
| 步骤 1 后出现六条 `CS0234`，提示 `Game.Debug` 没有 `Log`/`LogError` | 这是 `Game.Debug` 遮蔽旧 `Debug.Log*` 的预期中间状态；继续完成步骤 2，不要额外添加 `Debug` 别名 |
| 所有项目日志都不出现 | `DebugSettings.Debug Enabled` 是否关闭；`DebugBootstrap.Settings` 是否漏拖 |
| Console 有消息、画面没有 | `Overlay Enabled` 是否开启；`DebugOverlay` 的 `Log Text` 是否已拖引用 |
| 画面有消息、Console 没有 | `Console Enabled` 是否关闭；Console 顶部的 Log/Warning/Error 过滤按钮是否被关 |
| 只有某个模块没消息 | `Enabled Categories` 是否勾选对应分类 |
| 输入缓冲文本为空 | 是否启用 `Input` 分类；`Player Input Handler` 是否拖了 Player 上的组件 |
| 修改对象池诊断开关后没变化 | `diagnosticsEnabled` 在 `Awake` 缓存；停止并重新进入 Play |
| 屏幕日志重复出现 | 检查 `DebugOverlay.OnDisable` 是否误写成 `Subscribe`；场景中是否挂了两个 Overlay |
| 删除旧脚本后出现 Missing Script | 先从旧 UI 物体移除 `DebugText` 组件，再删除脚本并保存场景 |

诊断顺序仍沿用项目已有经验：先看 Console 过滤按钮，再确认 Inspector 修改是否 `Ctrl+S` 保存，然后检查组件引用和 Unity 生命周期函数拼写，最后才怀疑核心逻辑。

## 设计边界与暂不实现的内容

本轮刻意不做以下扩展：

- 不写日志文件到磁盘；
- 不上传远程日志；
- 不接入第三方崩溃分析服务；
- 不做运行时调试命令行；
- 不拦截 Unity、Package 或第三方插件直接产生的所有 Console 消息；
- 不为每条日志建立新的 EventBus 事件类型。

这些能力会增加生命周期、权限、线程或隐私处理成本。V1.5 当前只需要一个足够小、能支持关卡生成诊断的本地系统。
