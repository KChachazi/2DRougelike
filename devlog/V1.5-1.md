# V1.5-1：武器/伤害深化 —— Decorator 装饰器 + 状态异常系统

> V1 六周结束后的第一个深化阶段。目标是让"伤害"不再只是一个整数——而是可以叠加灼烧、冰冻、击退等附加效果的**伤害包**，并且这些效果可以像垒积木一样自由组合："灼烧+冰冻的手枪"、"击退+灼烧的近战"……一切靠 Decorator 模式装饰，不改主体逻辑。
>
> 照旧:分 4 步,每步可编译、可 Play 验收。参考实现在 `Reference/Scripts/...`(与 `Assets/` 同级,不进版本库),你自己在 `Assets/Scripts/...` 对应路径创建/替换。不懂随时问。

## 本周目标

- **DamageInfo 伤害包**：用 `readonly struct` 取代原来满世界裸传 `int damage` 的做法，伤害、击退、状态异常三项数据一次打包。
- **StatusEffectManager 状态异常管理器**：挂载在敌人/玩家上，管理灼烧 DoT、冰冻减速、易伤倍率的生命周期（Tick、过期、刷新）。
- **Decorator 装饰器模式**：`IWeaponStrategy` 的 `Fire` 签名改为接受 `DamageInfo`，Burning / Freezing / Knockback 三个 ConcreteDecorator 可任意叠加。
- **WeaponData 元素字段**：在 Inspector 里就能给武器配灼烧/冰冻/击退，不写代码也能做元素武器。

完成后：手枪可以配"灼烧 3 秒，每 0.5 秒跳 3 点伤害"；近战可以配"冰冻减速 50%，持续 2 秒"；一把武器可以同时有灼烧+冰冻+击退。第 1~6 周所有功能保持不变。

## 0. 先理解两个核心概念

### 0.1 为什么要把 `int damage` 升级成 `DamageInfo`

现在的伤害链路是这样的——一发子弹从产生到消失,传播的是一个 `int`:

```
WeaponData.damage → Bullet.SetDamage(int) → Health.TakeDamage(int)
```

问题:如果你想让子弹"击中后附带灼烧效果",往哪塞?`int` 只有一个数字,塞不下"灼烧 3 跳"这条信息。你要么在 `Bullet` 里加字段,要么在 `Health` 硬编码 `if (weaponName == "火焰枪") StartCoroutine(Burn(...))`——每加一种元素效果就要改核心代码。

**DamageInfo 的做法**:把一次伤害的所有信息打包成一个结构体,整条链路传递这一个东西:

```
WeaponData → WeaponController.BuildDamageInfo() → DamageInfo
  → Decorator 链追加效果 → Strategy.Fire(DamageInfo) → Bullet.SetDamageInfo(DamageInfo)
  → 命中后: Health.TakeDamage(DamageInfo) + StatusEffectManager.ApplyEffects(DamageInfo)
```

以后加新效果不用改 Bullet、不用改 Strategy——只在 WeaponData 加字段(Inspector 配置)或在外面包一个 Decorator(代码组合)。

### 0.2 Decorator 模式是什么、为什么在这里用

你已经有 `IWeaponStrategy` 接口了,有两个实现:`RangedWeaponStrategy`(发子弹)、`MeleeWeaponStrategy`(画圈砍)。

现在想做一把"灼烧手枪"——一种做法是写一个 `BurningRangedWeaponStrategy`,把 Ranged 的代码抄一遍,末尾加一行"给子弹附加灼烧"。但这会导致:每种元素 × 每种基础策略 = 类爆炸(3 元素 × 2 策略 = 6 个类)。再加一种元素就是 8 个类。

**Decorator 模式**:写一个"包装器"类,它也实现 `IWeaponStrategy`,同时持有另一个 `IWeaponStrategy`。`Fire()` 时先做一些事(比如把灼烧效果追加到 DamageInfo 上),再调用被它包着的那个策略的 `Fire()`。你可以无限层叠:

```
new BurningDecorator(
    new FreezingDecorator(
        new RangedWeaponStrategy(), freezeConfig),
    burnConfig)
```

三种元素 + 两种基础策略 = 3 个 Decorator + 2 个基础策略 = 5 个类。加第四种元素只加 1 个 Decorator,不碰其他代码。

和项目已有的"策略模式"相比:

| 模式 | 接口 | 怎么加新东西 |
|------|------|-------------|
| Strategy(已有) | `IWeaponStrategy` → Ranged/Melee | 写一个新策略类 |
| Decorator(本周) | `IWeaponStrategy` → Decorator 包 Strategy | 写一个新 Decorator,**不碰原有策略** |

两者共用一个接口,所以能混用——这就是 V1 架构的前瞻性回报。

## 步骤 1:地基——DamageInfo + StatusEffectTypes + StatusEffectManager

**这一步做什么**:把"伤害"的概念从 `int` 升级为 `DamageInfo`,同时创建状态异常管理器。这一步做完还不能 Play,因为其他文件还没适配,但**编译必须通过**。

### 1.1 新建 `Assets/Scripts/Core/StatusEffectTypes.cs`

参考实现:`Reference/Scripts/Core/StatusEffectTypes.cs`。

```csharp
namespace Game.Core
{
    /// <summary>
    /// 状态异常类型。
    /// Knockback 不在此列——它是一次性冲量而非持续状态，走 DamageInfo.KnockbackForce。
    /// </summary>
    public enum StatusType
    {
        Burn,       // 灼烧：持续扣血（DoT）
        Freeze,     // 冰冻：减速
        Vulnerable, // 易伤：受到伤害增加
    }

    /// <summary>
    /// 单条状态异常的配置数据。
    /// 出现在两个地方：
    /// ① WeaponData（武器自带的基础效果，在 Inspector 里配置）
    /// ② Decorator（运行时叠加的效果，由代码构造）
    ///
    /// 不同 StatusType 用到的字段不同，未用到的字段直接忽略：
    ///   Burn       → damagePerTick / tickInterval / duration
    ///   Freeze     → slowPercent / duration
    ///   Vulnerable → damageMultiplier / duration
    /// </summary>
    [System.Serializable]
    public struct StatusEffectConfig
    {
        public StatusType Type;

        /// <summary>效果持续时间（秒）</summary>
        public float Duration;

        // ---- Burn 专用 ----
        /// <summary>每次跳字的伤害量</summary>
        public int DamagePerTick;
        /// <summary>跳字间隔（秒），默认 0.5</summary>
        public float TickInterval;

        // ---- Freeze 专用 ----
        /// <summary>减速比例：0.3 = 减速 30%（移速变为原来的 70%）</summary>
        public float SlowPercent;

        // ---- Vulnerable 专用 ----
        /// <summary>受伤倍率：1.5 = 受到 150% 伤害</summary>
        public float DamageMultiplier;

        /// <summary>
        /// 快捷构造：灼烧效果。
        /// </summary>
        public static StatusEffectConfig Burn(float duration, int damagePerTick, float tickInterval = 0.5f)
        {
            return new StatusEffectConfig
            {
                Type = StatusType.Burn,
                Duration = duration,
                DamagePerTick = damagePerTick,
                TickInterval = tickInterval,
            };
        }

        /// <summary>
        /// 快捷构造：冰冻减速效果。
        /// </summary>
        public static StatusEffectConfig Freeze(float duration, float slowPercent)
        {
            return new StatusEffectConfig
            {
                Type = StatusType.Freeze,
                Duration = duration,
                SlowPercent = slowPercent,
            };
        }

        /// <summary>
        /// 快捷构造：易伤效果。
        /// </summary>
        public static StatusEffectConfig Vulnerable(float duration, float damageMultiplier)
        {
            return new StatusEffectConfig
            {
                Type = StatusType.Vulnerable,
                Duration = duration,
                DamageMultiplier = damageMultiplier,
            };
        }
    }
}
```

> **关键设计点**：
>
> - `StatusEffectConfig` 是 `[System.Serializable]` struct——可以内联在数组中(无额外 GC),也可以作为 `WeaponData` 的字段在 Inspector 里编辑。
> - 三个静态工厂方法 `Burn()`/`Freeze()`/`Vulnerable()` 只是语法糖,让你在代码里构造时不用一个个填字段。和 Decorator 配合使用时非常方便。
> - **Knockback 不放在 StatusType 里**:击退是"推一下",不是"每秒烧一下"。它没有 duration、不需要每帧 Tick,放在 StatusType 里会让 `ActiveStatus` 对不同类型做两套完全不同的处理。把它独立成 `DamageInfo.KnockbackForce` 更干净。

### 1.2 新建 `Assets/Scripts/Core/DamageInfo.cs`

参考实现:`Reference/Scripts/Core/DamageInfo.cs`。

```csharp
namespace Game.Core
{
    /// <summary>
    /// 一次伤害的完整信息包。
    /// 取代原来满世界裸传 int damage 的做法——
    /// 从 WeaponData → Strategy → Bullet → Health 整条链路都走这一个结构体。
    ///
    /// readonly struct：和项目里 GameEvents 的所有事件保持一致，
    /// 不可变、无 GC、线程安全。
    /// </summary>
    public readonly struct DamageInfo
    {
        /// <summary>基础伤害值</summary>
        public readonly int Amount;

        /// <summary>击退力度。0 表示没有击退。</summary>
        public readonly float KnockbackForce;

        /// <summary>命中时附加的状态异常列表（可为空）</summary>
        public readonly StatusEffectConfig[] StatusEffects;

        public DamageInfo(int amount, float knockbackForce = 0f, StatusEffectConfig[] effects = null)
        {
            Amount = amount;
            KnockbackForce = knockbackForce;
            StatusEffects = effects ?? System.Array.Empty<StatusEffectConfig>();
        }

        /// <summary>返回一份 Amount 不同的副本，其余字段不变。</summary>
        public DamageInfo WithAmount(int newAmount)
        {
            return new DamageInfo(newAmount, KnockbackForce, StatusEffects);
        }

        /// <summary>返回一份追加了击退的副本。</summary>
        public DamageInfo WithKnockback(float force)
        {
            return new DamageInfo(Amount, force, StatusEffects);
        }

        /// <summary>返回一份追加了状态异常的副本（原数组不变）。</summary>
        public DamageInfo WithAddedStatus(StatusEffectConfig effect)
        {
            var newEffects = new StatusEffectConfig[StatusEffects.Length + 1];
            System.Array.Copy(StatusEffects, newEffects, StatusEffects.Length);
            newEffects[StatusEffects.Length] = effect;
            return new DamageInfo(Amount, KnockbackForce, newEffects);
        }

        /// <summary>返回一份追加了击退 + 状态异常的副本。</summary>
        public DamageInfo WithKnockbackAndStatus(float force, StatusEffectConfig effect)
        {
            var newEffects = new StatusEffectConfig[StatusEffects.Length + 1];
            System.Array.Copy(StatusEffects, newEffects, StatusEffects.Length);
            newEffects[StatusEffects.Length] = effect;
            return new DamageInfo(Amount, force, newEffects);
        }

        // ---- 调试 ----
        public override string ToString()
        {
            return $"DamageInfo(amount={Amount}, knockback={KnockbackForce}, effects={StatusEffects.Length})";
        }
    }
}
```

> **为什么是 `readonly struct`**:项目的 `GameEvents.cs` 里所有事件都是 `readonly struct`——不可变、无 GC、线程安全。`DamageInfo` 数据量很小(int + float + 小数组引用),栈上传递比堆分配高效。
>
> **`WithXxx` 方法**:每个方法都返回**新**的 `DamageInfo` 实例,不修改原值。这就是不可变对象的标准做法——Decorator 链上每个 Decorator 调一次 `WithAddedStatus`,就像洋葱一样一层层包上去,最终传给 Strategy 的 DamageInfo 是"所有层都包完"的结果。
>
> **数组拷贝的成本**:`WithAddedStatus` 里 `new` 了一个新数组然后 `Array.Copy`,这在 C# 里是堆分配。但每发子弹才调用一次(频率远低于每帧),且 Decorator 链最多 3~5 层,开销完全可接受。如果将来要极致优化,可以用 `List<StatusEffectConfig>` 池化,但现阶段没必要。

### 1.3 新建 `Assets/Scripts/Entities/StatusEffectManager.cs`

参考实现:`Reference/Scripts/Entities/StatusEffectManager.cs`。

```csharp
using System.Collections.Generic;
using Game.Core;
using UnityEngine;

namespace Game.Entities
{
    /// <summary>
    /// 状态异常管理器——挂载在需要接收状态异常的实体上（敌人、玩家）。
    ///
    /// 职责：
    ///   1. 接收 DamageInfo 中携带的 StatusEffectConfig 列表，激活对应效果
    ///   2. 每帧 Update 中 Tick 所有激活的效果（DoT 扣血、减速、易伤过期等）
    ///   3. 对外暴露复合后的修饰值（SpeedMultiplier / DamageMultiplier），
    ///      供 EnemyController / Health 在移动/扣血时查询
    ///
    /// 使用方式：
    ///   - 在编辑器里给 Enemy/Player 预制体挂上这个组件
    ///   - Bullet / MeleeStrategy 命中后调用 ApplyEffects(damageInfo)
    ///   - 同一 GameObject 上的 Health / EnemyController 通过 GetComponent 找到它
    ///
    /// 和 Health 的分工：
    ///   Health 只管 HP（扣血、死亡、无敌帧）
    ///   StatusEffectManager 只管 BUFF/DEBUFF（DoT、减速、易伤）
    ///   两者靠 DamageInfo 衔接——Health 读 Amount / KnockbackForce，
    ///   StatusEffectManager 读 StatusEffects。
    /// </summary>
    public class StatusEffectManager : MonoBehaviour
    {
        [Header("击退")]
        [Tooltip("击退初速度（会被 Rigidbody2D drag 衰减）")]
        [SerializeField] private float knockbackSpeed = 8f;

        // ---- 内部状态 ----
        private readonly List<ActiveStatus> activeList = new List<ActiveStatus>();
        private Health health;
        private Rigidbody2D rb;

        /// <summary>
        /// 当前综合移速倍率（所有 Freeze 效果取最慢者）。
        /// 1.0 = 正常移速，0.5 = 减速 50%。
        /// EnemyController 的移动方法应乘以这个值。
        /// </summary>
        public float SpeedMultiplier { get; private set; } = 1f;

        /// <summary>
        /// 当前综合受伤倍率（所有 Vulnerable 效果取最高者）。
        /// 1.0 = 正常受伤，1.5 = 受到 150% 伤害。
        /// Health.TakeDamage 内部应乘以这个值。
        /// </summary>
        public float DamageMultiplier { get; private set; } = 1f;

        /// <summary>只读：当前激活的效果数量（调试用）</summary>
        public int ActiveCount => activeList.Count;

        private void Awake()
        {
            health = GetComponent<Health>();
            rb = GetComponent<Rigidbody2D>();
        }

        private void Update()
        {
            if (activeList.Count == 0) return;

            float dt = Time.deltaTime;
            bool needRecalc = false;

            // 倒序遍历，方便删除过期效果
            for (int i = activeList.Count - 1; i >= 0; i--)
            {
                ActiveStatus active = activeList[i];
                active.RemainingDuration -= dt;

                if (active.RemainingDuration <= 0f)
                {
                    activeList.RemoveAt(i);
                    needRecalc = true;
                    continue;
                }

                // Burn: DoT 计时
                if (active.Config.Type == StatusType.Burn)
                {
                    active.TickTimer -= dt;
                    if (active.TickTimer <= 0f)
                    {
                        active.TickTimer = active.Config.TickInterval;
                        // 每跳扣血（不受 DamageMultiplier 影响——易伤不双倍扣 DoT）
                        if (health != null)
                        {
                            health.TakeDamage(active.Config.DamagePerTick);
                        }
                    }
                }
            }

            if (needRecalc)
            {
                RecalcModifiers();
            }
        }

        // ==================== 公开接口 ====================

        /// <summary>
        /// 对实体施加 DamageInfo 中携带的所有状态异常。
        /// 由 Bullet、MeleeStrategy、Grenade 等命中逻辑调用。
        /// </summary>
        public void ApplyEffects(DamageInfo info)
        {
            if (info.StatusEffects == null || info.StatusEffects.Length == 0) return;

            foreach (var config in info.StatusEffects)
            {
                ApplyEffect(config);
            }
        }

        /// <summary>
        /// 施加单条状态异常。
        /// 同类型效果会取剩余时间较长者（而非叠加）。
        /// </summary>
        public void ApplyEffect(StatusEffectConfig config)
        {
            if (config.Duration <= 0f) return;

            // 查找是否已有同类型效果
            for (int i = 0; i < activeList.Count; i++)
            {
                if (activeList[i].Config.Type == config.Type)
                {
                    ActiveStatus existing = activeList[i];

                    // 只延长持续时间，不重置 tickTimer（保持原有的跳字节奏）
                    if (config.Duration > existing.RemainingDuration)
                        existing.RemainingDuration = config.Duration;

                    // 如果新的 tickInterval 更短（更快），替换成新的（"更强的灼烧"）
                    if (config.Type == StatusType.Burn && config.TickInterval < existing.Config.TickInterval)
                    {
                        existing.Config = config;
                        existing.TickTimer = Mathf.Min(existing.TickTimer, config.TickInterval);
                    }
                    return;
                }
            }

            // 新效果
            activeList.Add(new ActiveStatus
            {
                Config = config,
                RemainingDuration = config.Duration,
                TickTimer = config.TickInterval, // Burn 的首次跳字间隔
            });

            RecalcModifiers();
        }

        /// <summary>
        /// 施加击退冲量。
        /// 由 Bullet / MeleeStrategy 在命中时调用。
        /// direction 是击退方向（通常是从伤害源指向被击中者）。
        /// </summary>
        public void ApplyKnockback(Vector2 direction, float force)
        {
            if (rb == null || force <= 0f) return;

            // 清掉当前速度后施加瞬时冲量
            rb.linearVelocity = direction.normalized * knockbackSpeed * force;
        }

        /// <summary>
        /// 立即清除所有状态异常（关卡切换、实体死亡等场景）。
        /// </summary>
        public void ClearAll()
        {
            activeList.Clear();
            RecalcModifiers();
        }

        // ==================== 内部 ====================

        private void RecalcModifiers()
        {
            // SpeedMultiplier: 取所有 Freeze 中最慢的那个
            float minSpeed = 1f;
            // DamageMultiplier: 取所有 Vulnerable 中最高的那个
            float maxDmg = 1f;

            for (int i = 0; i < activeList.Count; i++)
            {
                var cfg = activeList[i].Config;
                switch (cfg.Type)
                {
                    case StatusType.Freeze:
                        float s = 1f - cfg.SlowPercent;
                        if (s < minSpeed) minSpeed = s;
                        break;
                    case StatusType.Vulnerable:
                        if (cfg.DamageMultiplier > maxDmg) maxDmg = cfg.DamageMultiplier;
                        break;
                }
            }

            SpeedMultiplier = minSpeed;
            DamageMultiplier = maxDmg;
        }

        // ==================== 内部类型 ====================

        /// <summary>
        /// 一条正在生效的状态异常（运行时数据，非配置）。
        /// </summary>
        private class ActiveStatus
        {
            public StatusEffectConfig Config;
            public float RemainingDuration;
            public float TickTimer; // Burn DoT 专用：距离下一次跳字还有多久
        }
    }
}
```

> **这个类的核心逻辑**:
>
> - **Update() 里只做两件事**:① 倒计时 duration、过期就删;② Burn 类型倒计时 tickTimer、到 0 就扣一次血然后重置 timer。
> - **同类型刷新规则**:再次施加同类型效果,**只延长 `remainingDuration`**（取 max），不重置 tickTimer——也就是说灼烧的跳字节奏保持不变，只是持续更久。如果新的 tickInterval 更短（间隔更短 = 跳字更快 = 更强的灼烧），则替换配置并使 tickTimer 同步缩短到不超过新间隔。**不叠加 DoT 层数**——同类型效果永远只有一条。以后想改成"可叠 N 层"只改这个方法的 `return` 逻辑。
> - **复合倍率采用"惰性重算"**:`RecalcModifiers()` 只在效果增删时调用(不是每帧),O(n)扫一遍,效果数量通常 ≤ 5,开销可忽略。
> - **`ActiveStatus` 是内部 private class**:外部永远不需要知道"一个正在生效的效果"是什么——它只需读到 `SpeedMultiplier` 和 `DamageMultiplier`。

## 步骤 2:接口升级——IWeaponStrategy + WeaponData + Bullet + Ranged/Melee 策略

**这一步做什么**:修改武器系统的数据契约,让 `IWeaponStrategy.Fire()` 接受 `DamageInfo` 而不是 `WeaponData`,让子弹携带 `DamageInfo` 而不是 `int`。这一步做完,远程/近战两套策略都能编译通过,但 WeaponController 还没改。

### 2.1 更新 `Assets/Scripts/Weapons/IWeaponStrategy.cs`

参考实现:`Reference/Scripts/Weapons/IWeaponStrategy.cs`。

```csharp
using Game.Core;

namespace Game.Weapons
{
    /// <summary>
    /// 武器开火策略接口。
    ///
    /// V1.5 变更：参数从 (WeaponController, WeaponData) 变为
    /// (WeaponController, DamageInfo)。DamageInfo 是一个完整的伤害包——
    /// 包含基础伤害、击退力度和状态异常列表。
    ///
    /// 这个变更的意义：
    ///   - 策略不再需要关心 WeaponData 的结构（"我要读哪个字段"）
    ///   - 策略只负责"把 DamageInfo 投送出去"（子弹 / 近战判定）
    ///   - Decorator 可以在调用链上修改 DamageInfo，不碰策略本身
    ///
    /// 所有 IWeaponStrategy 实现（Ranged / Melee / 各种 Decorator）
    /// 都必须同步更新签名。
    /// </summary>
    public interface IWeaponStrategy
    {
        void Fire(WeaponController controller, DamageInfo damageInfo);
    }
}
```

```csharp
using Game.Core;
using Game.Entities;
using UnityEngine;

namespace Game.Weapons
{
    [RequireComponent(typeof(Rigidbody2D))]
    public class Bullet : MonoBehaviour, IPoolable
    {
        [SerializeField] private float speed = 15f;
        [SerializeField] private float lifeTime = 2f;
        [Tooltip("兜底伤害：当 SetDamageInfo 从未被调用时使用")]
        [SerializeField] private int fallbackDamage = 10;

        private Rigidbody2D rb;
        private float timer;

        /// <summary>
        /// V1.5：子弹携带的完整伤害信息，替代原来的 int damage。
        /// 由 RangedWeaponStrategy.Fire() 在 spawn 后通过 SetDamageInfo() 注入。
        /// </summary>
        private DamageInfo damageInfo;

        public ObjectPool Pool { get; set; }

        private void Awake()
        {
            rb = GetComponent<Rigidbody2D>();
            damageInfo = new DamageInfo(fallbackDamage);
        }

        private void OnEnable()
        {
            timer = 0f;
        }

        private void FixedUpdate()
        {
            rb.linearVelocity = transform.right * speed;
            timer += Time.fixedDeltaTime;
            if (timer >= lifeTime)
                ReturnToPool();
        }

        private void OnTriggerEnter2D(Collider2D other)
        {
            if (!other.CompareTag("Enemy")) return;

            // --- 1. 扣血 ---
            if (other.TryGetComponent(out Health health))
                health.TakeDamage(damageInfo);

            // --- 2. 状态异常 + 击退 ---
            if (other.TryGetComponent(out StatusEffectManager statusManager))
            {
                statusManager.ApplyEffects(damageInfo);

                if (damageInfo.KnockbackForce > 0f)
                {
                    Vector2 knockDir = ((Vector2)other.transform.position - rb.position).normalized;
                    statusManager.ApplyKnockback(knockDir, damageInfo.KnockbackForce);
                }
            }

            ReturnToPool();
        }

        private void ReturnToPool()
        {
            rb.linearVelocity = Vector2.zero;
            if (Pool != null)
                Pool.Release(gameObject);
            else
                Destroy(gameObject);
        }

        // ========== 公开接口 ==========

        /// <summary>
        /// V1.5 主入口：设置子弹的完整伤害信息。
        /// 替代原来的 SetDamage(int)。
        /// </summary>
        public void SetDamageInfo(DamageInfo info) => damageInfo = info;

        /// <summary>
        /// 向后兼容包装：仅设置伤害数值（无击退、无状态异常）。
        /// 新代码应优先使用 SetDamageInfo。
        /// </summary>
        public void SetDamage(int value) => damageInfo = new DamageInfo(value);
    }
}
```

> **变更要点**:
> - `int damage` → `DamageInfo damageInfo`
> - `SetDamage(int)` 保留(向后兼容),内部构造一个无效果无击退的 DamageInfo。旧代码如果还有地方只传 int,不会坏。
> - `OnTriggerEnter2D` 命中后的逻辑从"只调 `health.TakeDamage(damage)`"变成"先调 Health 扣血,再调 StatusEffectManager 施加状态异常和击退"。
> - **击退方向** = 从子弹指向敌人。`(enemyPosition - bulletPosition).normalized`。子弹从左边飞来,敌人朝左后方弹开——这在直觉上是正确的。

### 2.5 更新 `Assets/Scripts/Weapons/MeleeWeaponStrategy.cs`

参考实现:`Reference/Scripts/Weapons/MeleeWeaponStrategy.cs`。

```csharp
using Game.Core;
using Game.Entities;
using UnityEngine;

namespace Game.Weapons
{
    /// <summary>
    /// 近战武器策略：在角色前方做 OverlapCircle 判定，对范围内所有敌人
    /// 施加 DamageInfo（伤害 + 状态异常 + 击退）。
    ///
    /// V1.5 变更：除了扣血，还会对命中目标调用
    /// StatusEffectManager.ApplyEffects() 和 ApplyKnockback()。
    /// </summary>
    public class MeleeWeaponStrategy : IWeaponStrategy
    {
        private const int MaxHits = 16;
        private readonly Collider2D[] hitBuffer = new Collider2D[MaxHits];
        private readonly ContactFilter2D filter = ContactFilter2D.noFilter;

        public void Fire(WeaponController controller, DamageInfo damageInfo)
        {
            float range = controller.CurrentWeaponRange;
            Vector2 origin = (Vector2)controller.transform.position
                           + (Vector2)controller.transform.right * range;

            int count = Physics2D.OverlapCircle(origin, range, filter, hitBuffer);
            for (int i = 0; i < count; i++)
            {
                Collider2D hit = hitBuffer[i];
                if (!hit.CompareTag("Enemy")) continue;

                // ---- 伤害 ----
                if (hit.TryGetComponent(out Health health))
                    health.TakeDamage(damageInfo);

                // ---- 状态异常 + 击退 ----
                if (hit.TryGetComponent(out StatusEffectManager statusManager))
                {
                    statusManager.ApplyEffects(damageInfo);

                    if (damageInfo.KnockbackForce > 0f)
                    {
                        Vector2 knockDir = ((Vector2)hit.transform.position - origin).normalized;
                        statusManager.ApplyKnockback(knockDir, damageInfo.KnockbackForce);
                    }
                }
            }
        }
    }
}
```

> 相比远程策略,近战的改动多了一个点:**判定半径从 `controller.CurrentWeaponRange` 读取**(而不是从 WeaponData 取——因为策略不再认识 WeaponData)。`CurrentWeaponRange` 是 WeaponController 上新增的属性(步骤 3 会加),直接返回当前武器的 `range` 字段。

### 3.1 新建 `Assets/Scripts/Weapons/WeaponStrategyDecorator.cs`

参考实现:`Reference/Scripts/Weapons/WeaponStrategyDecorator.cs`。

```csharp
using Game.Core;

namespace Game.Weapons
{
    /// <summary>
    /// 武器策略装饰器抽象基类——Decorator 模式的 "Decorator" 角色。
    ///
    /// 继承自 IWeaponStrategy，同时持有一个 inner IWeaponStrategy，
    /// 默认实现就是直接转发给 inner。子类 override Fire() 来注入额外行为。
    ///
    /// 使用示例（代码构造）：
    ///   IWeaponStrategy rifle = new RangedWeaponStrategy();
    ///   IWeaponStrategy burningRifle = new BurningDecorator(rifle, burnConfig);
    ///   // burningRifle.Fire() 会先让 rifle 开火，然后给子弹附加灼烧
    ///
    /// 使用示例（WeaponController 自动装配）：
    ///   IWeaponStrategy strategy = new RangedWeaponStrategy();
    ///   if (weaponData.burnDamage > 0)
    ///       strategy = new BurningDecorator(strategy, StatusEffectConfig.Burn(...));
    ///   if (weaponData.freezePercent > 0)
    ///       strategy = new FreezingDecorator(strategy, StatusEffectConfig.Freeze(...));
    ///   // 最终 strategy 可能是三层嵌套：Knockback → Freeze → Burning → Ranged
    ///
    /// 为什么这个类存在：
    ///   三个具体装饰器（Burning/Freezing/Knockback）共享同一个模式——
    ///   "修改 DamageInfo → 调用 inner.Fire()"。
    ///   把共性的 inner 持有 + 构造函数抽到基类，避免每个装饰器重复。
    /// </summary>
    public abstract class WeaponStrategyDecorator : IWeaponStrategy
    {
        protected readonly IWeaponStrategy inner;

        protected WeaponStrategyDecorator(IWeaponStrategy inner)
        {
            this.inner = inner;
        }

        /// <summary>
        /// 子类必须 override。
        /// 典型实现：修改 damageInfo → inner.Fire(controller, modifiedInfo)。
        /// </summary>
        public abstract void Fire(WeaponController controller, DamageInfo damageInfo);
    }
}
```

> 这个抽象基类非常薄——只保存 inner 策略引用 + 声明 `Fire` 由子类实现。它的存在纯粹是为了**消除重复代码**:三个 Decorator 如果各自实现 `IWeaponStrategy` 并各自持有 inner,构造函数和 inner 字段都要在三个文件里各写一遍。抽到基类后,每个 ConcreteDecorator 只需要写自己的 `Fire()` 逻辑。

### 3.3 更新 `Assets/Scripts/Weapons/WeaponController.cs`

这是本次改动**最核心的文件**。参考实现:`Reference/Scripts/Weapons/WeaponController.cs`。

```csharp
using System.Collections.Generic;
using Game.Core;
using Game.Entities;
using UnityEngine;

namespace Game.Weapons
{
    public class WeaponController : MonoBehaviour
    {
        [SerializeField] private ObjectPool bulletPool;
        [SerializeField] private Transform firePoint;
        [Tooltip("按顺序对应数字键 1/2/3，元素 0 为初始武器")]
        [SerializeField] private WeaponData[] weapons;

        public ObjectPool BulletPool => bulletPool;
        public Transform FirePoint => firePoint;
        public int WeaponCount => weapons.Length;

        /// <summary>
        /// V1.5：近战策略需要知道判定半径，由 WeaponController 从这里暴露。
        /// MeleeWeaponStrategy.Fire() 中读取。
        /// </summary>
        public float CurrentWeaponRange => weapons[currentIdx].range;

        private PlayerController playerController;

        /// <summary>
        /// V1.5 变更：每把武器各持有一个独立的 IWeaponStrategy 实例，
        /// 而不像之前那样所有同类型武器共享一个策略。
        /// 这是因为 Decorator 链可能每把武器不同——
        /// "灼烧手枪"和"冰冻步枪"虽然都是 Ranged，但策略层已经不同了。
        /// </summary>
        private IWeaponStrategy[] weaponStrategies;

        private int currentIdx;
        private int[] currentAmmo;
        private float cooldownTimer;

        private WeaponData CurrentWeapon => weapons[currentIdx];

        private void Awake()
        {
            playerController = GetComponent<PlayerController>();

            // 为每把武器构造独立的策略实例 + Decorator 链
            weaponStrategies = new IWeaponStrategy[weapons.Length];
            for (int i = 0; i < weapons.Length; i++)
            {
                weaponStrategies[i] = BuildStrategy(weapons[i]);
            }

            currentAmmo = new int[weapons.Length];
            for (int i = 0; i < weapons.Length; i++)
                currentAmmo[i] = weapons[i].maxAmmo;
        }

        private void Start()
        {
            BroadcastWeapon();
            BroadcastAmmo();
        }

        private void Update()
        {
            if (cooldownTimer > 0f) cooldownTimer -= Time.deltaTime;
        }

        // ========== 策略构造（Decorator 装配线） ==========

        /// <summary>
        /// V1.5 核心装配方法：根据 WeaponData 构造出完整的 IWeaponStrategy 链。
        ///
        /// 链路：最内层是基础策略（Ranged / Melee），外层按需包裹 Decorator。
        /// 最终调用时数据流是：
        ///   BuildDamageInfo(SO) → KnockbackDecorator → FreezingDecorator
        ///   → BurningDecorator → RangedWeaponStrategy.Fire(最终 DamageInfo)
        ///
        /// 新增元素效果只需在 WeaponData 加字段 + 在这里加一行 if + Decorator。
        /// </summary>
        private IWeaponStrategy BuildStrategy(WeaponData data)
        {
            IWeaponStrategy strategy = data.type == WeaponType.Ranged
                ? new RangedWeaponStrategy()
                : new MeleeWeaponStrategy();

            // 从最内层往外包——Fire 时的调用顺序是"最外层 Decorator 先执行"。
            // 烧 → 冻 → 击退 → 基础策略，这样 DamageInfo 会依次被三者增强。

            if (data.burnDamagePerTick > 0 && data.burnDuration > 0f)
            {
                strategy = new BurningDecorator(strategy, data.burnDuration,
                    data.burnDamagePerTick, data.burnTickInterval);
            }

            if (data.freezePercent > 0f && data.freezeDuration > 0f)
            {
                strategy = new FreezingDecorator(strategy, data.freezeDuration, data.freezePercent);
            }

            if (data.knockbackForce > 0f)
            {
                strategy = new KnockbackDecorator(strategy, data.knockbackForce);
            }

            return strategy;
        }

        // ========== 公开接口 ==========

        public bool CanFire()
        {
            bool canAct = playerController == null || playerController.CanAct;
            return canAct && cooldownTimer <= 0f && HasAmmo();
        }

        public void Fire()
        {
            WeaponData data = CurrentWeapon;

            // V1.5：从 WeaponData 构造初始 DamageInfo
            DamageInfo damageInfo = BuildDamageInfo(data);

            // 调用当前武器的策略（可能已被 Decorator 包裹）
            weaponStrategies[currentIdx].Fire(this, damageInfo);

            cooldownTimer = data.cooldown;

            if (data.maxAmmo >= 0)
            {
                currentAmmo[currentIdx]--;
                BroadcastAmmo();
            }

            if (data.type == WeaponType.Melee && playerController != null)
                playerController.TriggerAttack();
        }

        public void SwitchTo(int index)
        {
            if (index < 0 || index >= weapons.Length || index == currentIdx) return;
            currentIdx = index;
            cooldownTimer = 0f;
            BroadcastWeapon();
            BroadcastAmmo();
        }

        public void AddAmmo(int amount)
        {
            WeaponData data = CurrentWeapon;
            if (data.maxAmmo < 0) return;
            currentAmmo[currentIdx] = Mathf.Min(currentAmmo[currentIdx] + amount, data.maxAmmo);
            BroadcastAmmo();
        }

        // ========== 内部 ==========

        /// <summary>
        /// V1.5：从 WeaponData 构造初始 DamageInfo。
        /// 这里读出基础伤害 + SO 上配置的元素效果字段。
        /// 生成的 DamageInfo 随后会经过 Decorator 链进一步叠加。
        /// </summary>
        private DamageInfo BuildDamageInfo(WeaponData data)
        {
            DamageInfo info = new DamageInfo(data.damage, data.knockbackForce);

            // 从 SO 字段构造状态异常（和 Decorator 是"叠加"关系）
            if (data.burnDamagePerTick > 0 && data.burnDuration > 0f)
            {
                info = info.WithAddedStatus(StatusEffectConfig.Burn(
                    data.burnDuration, data.burnDamagePerTick, data.burnTickInterval));
            }

            if (data.freezePercent > 0f && data.freezeDuration > 0f)
            {
                info = info.WithAddedStatus(StatusEffectConfig.Freeze(
                    data.freezeDuration, data.freezePercent));
            }

            return info;
        }

        private bool HasAmmo() => CurrentWeapon.maxAmmo < 0 || currentAmmo[currentIdx] > 0;

        private void BroadcastAmmo() =>
            EventBus.Publish(new AmmoChangedEvent(currentAmmo[currentIdx], CurrentWeapon.maxAmmo));

        private void BroadcastWeapon() =>
            EventBus.Publish(new WeaponChangedEvent(CurrentWeapon.weaponName));
    }
}
```

> **关键架构变更**:
>
> 1. **从 `Dictionary<WeaponType, IWeaponStrategy>` 变成 `IWeaponStrategy[]`**:旧方案所有同类型武器共享一个策略实例;新方案每把武器有独立的策略链,因为"灼烧手枪"和"冰冻步枪"虽然都是 Ranged,但策略层已经被不同的 Decorator 包裹成了不同的对象。
>
> 2. **`BuildDamageInfo(WeaponData)`**:从 SO 字段构造初始 DamageInfo。如果有 `burnDamagePerTick > 0`,就追加一条 Burn。如果 `freezePercent > 0`,就追加一条 Freeze。`knockbackForce` 直接写在构造函数里(因为它是 DamageInfo 的顶层字段,不是 StatusEffects 数组的元素)。
>
> 3. **`BuildStrategy(WeaponData)`**:构造基础策略 + 按需包 Decorator。**包的方向是从内到外**:先创建 Ranged/Melee,然后判断 `data.burnDamagePerTick>0` → 包一层 BurningDecorator,再判断 `data.freezePercent>0` → 包一层 FreezingDecorator……这意味着 `Fire()` 被调用时,最外层 Decorator 先执行(往 DamageInfo 上加效果),然后依次往里传,最后基础策略收到的是"所有层都叠完"的 DamageInfo。
>
> 4. **`BuildDamageInfo` 和 `BuildStrategy` 对同一种效果都做了处理**:如果 SO 配了 Burn,`BuildDamageInfo` 会在初始 DamageInfo 里加一条 Burn,`BuildStrategy` 会包一个 `BurningDecorator`——最终 DamageInfo 里会有**两条** Burn 条目。但这没关系,因为 `StatusEffectManager.ApplyEffect` 对同类型只取 `max` 时长,不会双倍 DoT。这样设计的好处是:你可以只用 SO 字段(不写代码,只填 Inspector)、也可以只用 Decorator(代码构造,运行时动态决定),或者两者都用(SO 提供基础、Decorator 追加增强)——三个场景走同一条链路。

### 4.1 更新 `Assets/Scripts/Entities/Health.cs`

参考实现:`Reference/Scripts/Entities/Health.cs`。

```csharp
using System;
using Game.Core;
using UnityEngine;

namespace Game.Entities
{
    /// <summary>
    /// 通用血量组件。
    ///
    /// V1.5 变更：
    ///   1. 新增 TakeDamage(DamageInfo) 重载——从 DamageInfo 中提取 Amount，
    ///      并根据 StatusEffectManager.DamageMultiplier 调整最终伤害。
    ///   2. 原有的 TakeDamage(int) 保留作为内部 fallback（向后兼容）。
    ///
    /// 与 StatusEffectManager 的分工：
    ///   Health：管 HP（扣血、死亡、无敌帧）
    ///   StatusEffectManager：管 BUFF/DEBUFF（DoT、减速、易伤倍率）
    ///   两者的桥梁是 DamageInfo，由外部命中逻辑（Bullet / Melee / Grenade）
    ///   分别调用两者。
    /// </summary>
    public class Health : MonoBehaviour
    {
        [SerializeField] private int maxHealth = 100;
        public int Current { get; private set; }
        public int Max => maxHealth;
        public bool isDead => Current <= 0;
        public bool isInvincible { get; private set; }

        public event Action<int> Damaged;
        public event Action Died;
        public event Action<int, int> HealthChanged;

        private float invincibleTimer;
        private StatusEffectManager statusEffectManager;

        private void Awake()
        {
            Current = maxHealth;
            statusEffectManager = GetComponent<StatusEffectManager>();
        }

        private void Update()
        {
            if (!isInvincible) return;
            invincibleTimer -= Time.deltaTime;
            if (invincibleTimer <= 0f)
                isInvincible = false;
        }

        // ========== 公开接口（V1.5 推荐入口） ==========

        /// <summary>
        /// V1.5 主入口：接受 DamageInfo，自动处理易伤倍率。
        /// 新代码（Bullet、MeleeStrategy、Grenade 等）应使用此重载。
        /// </summary>
        public void TakeDamage(DamageInfo info)
        {
            if (isDead || isInvincible) return;

            // 易伤倍率：查询 StatusEffectManager
            float multiplier = 1f;
            if (statusEffectManager != null)
                multiplier = statusEffectManager.DamageMultiplier;

            int finalDamage = Mathf.Max(1, Mathf.RoundToInt(info.Amount * multiplier));
            ApplyDamage(finalDamage);
        }

        /// <summary>
        /// 向后兼容重载：仅接受整数伤害（无易伤倍率处理）。
        /// 内部逻辑和 V1 完全一致。Burn DoT / 旧代码仍可使用。
        /// </summary>
        public void TakeDamage(int amount)
        {
            if (isDead || isInvincible) return;
            ApplyDamage(amount);
        }

        /// <summary>无敌帧</summary>
        public void SetInvincible(float duration)
        {
            isInvincible = true;
            invincibleTimer = duration;
        }

        // ========== 内部 ==========

        private void ApplyDamage(int amount)
        {
            Current = Mathf.Max(0, Current - amount);
            Damaged?.Invoke(amount);
            HealthChanged?.Invoke(Current, maxHealth);
            if (isDead) Die();
        }

        private void Die()
        {
            Died?.Invoke();
            gameObject.SetActive(false);
        }
    }
}
```

> **两重重载共存**:
> - `TakeDamage(DamageInfo)` — Bullet、MeleeStrategy、Grenade 用,自动计算易伤倍率
> - `TakeDamage(int)` — Burn DoT 内部用,**不受易伤二次放大**(这是有意为之:易伤让每次命中伤害增加 50%,但不会让 DoT 也翻倍,避免"易伤 + 灼烧"的伤害量失控)
>
> `ApplyDamage(int)` 是两重重载的共同收束点,避免了"改一个忘记改另一个"的 bug。`SetInvincible` 保持不变。

```csharp
        [SerializeField] private int contactDamage = 10;
        [SerializeField] private float attackCooldown = 1f;

        public Rigidbody2D Rb { get; private set; }
        public Health health { get; private set; }
        public SpriteRenderer SpriteRenderer { get; private set; }
        public Color OriginalColor { get; private set; }
        public Transform Player { get; private set; }
        public Vector2 SpawnPosition { get; private set; }

        /// <summary>
        /// V1.5: StatusEffectManager 引用，供状态类在移动时读取 SpeedMultiplier。
        /// </summary>
        public StatusEffectManager StatusManager { get; private set; }

        public float PatrolSpeed => patrolSpeed;
        public float PatrolRadius => patrolRadius;
        public float ChaseSpeed => chaseSpeed;
        public float DetectionRange => detectionRange;
        public float LoseSightRange => loseSightRange;
        public float AttackRange => attackRange;
        public int ContactDamage => contactDamage;
        public float AttackCooldown => attackCooldown;

        public EnemyPatrolState PatrolState { get; private set; }
        public EnemyChaseState ChaseState { get; private set; }
        public EnemyAttackState AttackState { get; private set; }
        public EnemyDeadState DeadState { get; private set; }

        private readonly StateMachine stateMachine = new StateMachine();

        private void Awake()
        {
            Rb = GetComponent<Rigidbody2D>();
            health = GetComponent<Health>();
            SpriteRenderer = GetComponent<SpriteRenderer>();
            StatusManager = GetComponent<StatusEffectManager>();
            OriginalColor = SpriteRenderer.color;
            SpawnPosition = Rb.position;

            PatrolState = new EnemyPatrolState(this, stateMachine);
            ChaseState = new EnemyChaseState(this, stateMachine);
            AttackState = new EnemyAttackState(this, stateMachine);
            DeadState = new EnemyDeadState(this, stateMachine);
        }

        private void OnEnable()
        {
            health.Damaged += OnDamaged;
            health.Died += OnDied;
        }

        private void OnDisable()
        {
            health.Damaged -= OnDamaged;
            health.Died -= OnDied;
        }

        private void Start()
        {
            GameObject playerObj = GameObject.FindGameObjectWithTag("Player");
            if (playerObj != null)
                Player = playerObj.transform;

            stateMachine.ChangeState(PatrolState);
        }

        private void Update()
        {
            stateMachine.Tick();
        }

        private void FixedUpdate()
        {
            stateMachine.FixedTick();
        }

        public float DistanceToPlayer()
        {
            return Player == null ? float.MaxValue : Vector2.Distance(Rb.position, Player.position);
        }

        /// <summary>
        /// V1.5 更新：移动时自动乘以 StatusEffectManager.SpeedMultiplier，
        /// 使冰冻减速自动生效，无需每个状态类单独处理。
        ///
        /// 如果实体没有 StatusEffectManager（未挂载），倍率默认为 1.0。
        /// </summary>
        public void MoveTowards(Vector2 targetPosition, float speed)
        {
            float multiplier = StatusManager != null ? StatusManager.SpeedMultiplier : 1f;
            Vector2 direction = (targetPosition - Rb.position).normalized;
            Rb.MovePosition(Rb.position + direction * speed * multiplier * Time.fixedDeltaTime);
        }

        private void OnDamaged(int amount)
        {
            EventBus.Publish(new EnemyDamagedEvent(Rb.position, amount));
        }

        private void OnDied()
        {
            EventBus.Publish(new EnemyDiedEvent(Rb.position));
            stateMachine.ChangeState(DeadState);
        }
    }
}
```

> **改动极小但效果显著**:`MoveTowards` 里加了 `* multiplier`。因为 `MoveTowards` 是三个敌人状态(Patrol / Chase / Attack)共用的移动方法,在这里乘一次倍率,冰冻减速就在所有状态下自动生效。`StatusManager` 为 null 时倍率 = 1.0,所以没挂 StatusEffectManager 的敌人完全不受影响。

## 5. 设计决策记录

### 5.1 为什么 Knockback 不是 StatusType

击退是**一次性冲量**(`rb.linearVelocity = direction * speed`),不需要维持状态、不需要在 Update 里倒计时。而 Burn/Freeze/Vulnerable 都是**持续性效果**,有 duration、需要每帧 Tick。把它放 StatusType 里会导致 `ActiveStatus` 做两套完全不同的处理——不如直接拆到 `DamageInfo.KnockbackForce`。

### 5.2 为什么同类型效果是"取时长最大值"而不是叠加

"灼烧叠加"意味着 3 层灼烧同时跳动,每跳伤害 = `3 × damagePerTick`。玩法上有趣但会带来平衡噩梦(5 层 = 5 倍 DoT,瞬间蒸发)。当前选择保守起步——后续可以改成"可叠加 N 层"作为进阶特性,只需改 `ApplyEffect` 里的刷新逻辑。

### 5.3 为什么 WeaponData 上的字段和 Decorator 会重复

这是一个有意的冗余:

- **SO 字段**:面向关卡设计师——Inspector 填数字就能配元素武器,不写代码
- **Decorator**:面向程序员——运行时组合效果(比如根据敌人血量决定是否附加灼烧)

两者走同一条 `DamageInfo` 链路,在同类型效果上取 `max` 时长,不会叠加出双倍 DoT。以后只用一种方式就可以(删掉 SO 字段只用 Decorator,或者反过来)。

### 5.4 为什么不在 Health 里直接处理状态异常

每一层组件只做一件事:

- **Health**:管 HP(血量、无敌帧、死亡)
- **StatusEffectManager**:管 BUFF/DEBUFF(DoT 计时、倍率计算、过期)

这是 V1 就定下的组件拆分原则。不挂 StatusEffectManager 的敌人完全不受影响——`Bullet.OnTriggerEnter2D` 里的 `TryGetComponent<StatusEffectManager>` 返回 false,跳过所有状态异常逻辑,只扣血。

### 5.5 `IWeaponStrategy` 签名破坏性变更的取舍

旧接口 `Fire(WeaponController, WeaponData)` → 新接口 `Fire(WeaponController, DamageInfo)`。这是**全项目影响面最大的一次接口变更**,但也是最后一次——DamageInfo 是一个可扩展的容器,以后加新的伤害属性(暴击、护甲穿透)只需在 DamageInfo 上加字段 + `WithXxx` 方法,不再动接口。

## 6. 踩过的坑 & 注意事项

### 6.1 `TakeDamage(DamageInfo)` 和 `TakeDamage(int)` 共存

两个重载共存,C# 编译器能区分(参数类型不同)。但注意:Burn DoT 走 `int` 重载——**易伤倍率不会放大 DoT**。这是有意为之,如果以后要改,在 Burn tick 处改用 `DamageInfo` 重载即可。

### 6.2 击退后敌人一直漂

`ApplyKnockback` 直接设 `rb.linearVelocity` 后没有后续清零机制(Player 有 `FixedUpdate` 里的 `Rb.linearVelocity = Vector2.zero`,Enemy 没有)。给 Enemy 预制体的 Rigidbody2D 设 `Linear Drag = 5~8`,让击退冲量自然衰减。

### 6.3 `BuildDamageInfo` 和 `BuildStrategy` 对同一种效果都做了处理

如前所述,SO 字段 AND Decorator 同时对同一种效果追加,导致 DamageInfo 里出现两条同类型状态异常。`StatusEffectManager` 会取 `max(时长1, 时长2)`,不会叠加 DoT。但如果你故意想让 SO 字段和 Decorator 效果**不同**(比如 SO 是 burn 2 秒、Decorator 是 burn 5 秒,期待叠加成 7 秒)——当前行为是只保留 5 秒。如果要做叠加,改 `ApplyEffect` 里的刷新逻辑。

### 6.4 `MeleeStrategy` 里的 `controller.CurrentWeaponRange`

`CurrentWeaponRange` 是新增属性。如果将来 `WeaponController` 在别处被用到且没有 `weapons` 数组(边界情况),这里会 NRE。正常流程(Player 身上)不会触发。

## 9. 实际验收后的设计修正

> 以下两条是实际实现和 Play 测试后发现的架构问题,已在对话中讨论确认,记录在此供后续参考。

### 9.1 修正一：击退改成独立状态 `EnemyKnockbackState`

**原方案的问题**：

击退原本走 `StatusEffectManager.ApplyKnockback()`——对敌人的 Rigidbody2D 设 `linearVelocity` 或 `AddForce`。但敌人每帧 `FixedUpdate` 都在调 `MoveTowards` → `MovePosition`,MovePosition 无视 velocity,导致击退效果几乎看不见。

更根本的问题是——击退和灼烧/冰冻是**不同性质的东西**：

| | 持续 BUFF/DEBUFF | 击退 |
|---|---|---|
| 性质 | 数值修饰（扣血、减速、易伤） | **行为控制**（强制位移、不能还手） |
| 持续时间 | 1~5 秒 | 0.15~0.2 秒 |
| 归属 | `StatusEffectManager` 管 | **状态机**管 |
| 实现 | 每帧 Tick 效果 | 进入状态 → 平滑减速位移 → 退出状态 |

正确做法是新增一个状态，和 Patrol/Chase/Attack/Dead 平级。

**修正后的实现**：

文件路径：`Assets/Scripts/StateMachines/Enemy/EnemyKnockbackState.cs`

```csharp
using UnityEngine;

namespace Game.StateMachines.Enemy
{
    public class EnemyKnockbackState : IState
    {
        private readonly EnemyController enemy;
        private readonly StateMachine stateMachine;
        private float timer;
        private Vector2 direction;
        private float startSpeed;

        public EnemyKnockbackState(EnemyController enemy, StateMachine stateMachine)
        {
            this.enemy = enemy;
            this.stateMachine = stateMachine;
        }

        public void Enter()
        {
            direction = enemy.KnockbackDirection;
            startSpeed = enemy.KnockbackSpeed;
            timer = 0f;
            enemy.SpriteRenderer.color = Color.cyan;  // 击退时闪青（调试色）
        }

        public void Tick() { }

        public void FixedTick()
        {
            timer += Time.fixedDeltaTime;
            if (timer >= enemy.KnockbackDuration)
            {
                stateMachine.ChangeState(enemy.PatrolState);
                return;
            }

            // 速度线性衰减：开始快 → 结束慢 → 自然停止
            float t = timer / enemy.KnockbackDuration;
            float currentSpeed = Mathf.Lerp(startSpeed, 0f, t);
            enemy.Rb.MovePosition(
                enemy.Rb.position + direction * currentSpeed * Time.fixedDeltaTime);
        }

        public void Exit()
        {
            enemy.SpriteRenderer.color = enemy.OriginalColor;
        }
    }
}
```

`EnemyController` 需要增加的内容：

```csharp
// 新状态实例
public EnemyKnockbackState KnockbackState { get; private set; }

// 击退参数
[Header("击退")]
[SerializeField] private float knockbackDuration = 0.15f;
[SerializeField] private float knockbackSpeedMultiplier = 10f;

// 由外部（Bullet / Melee / Grenade）设置后立即被 KnockbackState.Enter 读取
public Vector2 KnockbackDirection { get; private set; }
public float KnockbackSpeed { get; private set; }
public float KnockbackDuration => knockbackDuration;

// Awake 里加：
KnockbackState = new EnemyKnockbackState(this, stateMachine);

// 新公开方法——替代原来的 StatusEffectManager.ApplyKnockback
public void TriggerKnockback(Vector2 direction, float force)
{
    KnockbackDirection = direction.normalized;
    KnockbackSpeed = knockbackSpeedMultiplier * force;
    stateMachine.ChangeState(KnockbackState);
}
```

命中端（`Bullet.OnTriggerEnter2D` / `MeleeWeaponStrategy.Fire`）中，原来的：

```csharp
statusEffectManager.ApplyKnockback(knockDir, damageInfo.KnockbackForce);
```

改为：

```csharp
if (other.TryGetComponent(out EnemyController enemyController))
    enemyController.TriggerKnockback(knockDir, damageInfo.KnockbackForce);
```

> 注意这里不再调 `StatusEffectManager`,而是直接调 `EnemyController`。击退不再属于 BUFF/DEBUFF 系统。

`StatusEffectManager` 中可删除的内容：
- `ApplyKnockback` 方法
- `knockbackSpeed` 字段
- `rb` 字段（如果只是为 ApplyKnockback 而缓存的话）

### 9.2 修正二：`BuildStrategy` 和 `BuildDamageInfo` 的重复设计

**问题**：两种方法在读取**同一份 WeaponData SO 的同一个字段**,然后通过不同路径写入 DamageInfo,导致每个效果都被加了两次。

以 knockback 为例：

```
WeaponData.knockbackForce = 1.0
          │
          ├── BuildDamageInfo()
          │   new DamageInfo(damage, 1.0)
          │   结果: DamageInfo{KnockbackForce = 1.0}
          │
          └── BuildStrategy()
              new KnockbackDecorator(strategy, 1.0)
              └─ .Fire() 内部:
                 damageInfo.WithKnockback(1.0)
                 结果: DamageInfo{KnockbackForce = 1.0}  ← 和上面一模一样
```

burn 和 freeze 同理——`BuildDamageInfo` 调 `WithAddedStatus(Burn)`, `BuildStrategy` 又包 `BurningDecorator`(内部也调 `WithAddedStatus(Burn)`)。只是因为 `StatusEffectManager.ApplyEffect` 对同类型取 max 时长,两条 Burn 被合并为一条,所以你没看到双倍 DoT 的 bug——但逻辑上就是重复的。

**为什么会出现这个重复**：我在设计时没想清楚"谁负责把 SO 字段翻译成 DamageInfo"。两种方案都能工作,但**不能同时用两种**。Decorator 的价值在于**运行时动态组合**（比如玩家捡到一个灼烧附件,所有武器自动附加灼烧）,而不是把编译时已知的 SO 字段再包一层。

**修正**：选择 `BuildDamageInfo` 作为唯一翻译路径（简单、直接、不改策略链）, `BuildStrategy` 精简为只创建基础策略,不再自动包裹 Decorator。

```csharp
// BuildStrategy 精简后
private IWeaponStrategy BuildStrategy(WeaponData data)
{
    return data.type == WeaponType.Ranged
        ? new RangedWeaponStrategy()
        : new MeleeWeaponStrategy();
}

// BuildDamageInfo 保持不变——它已经是唯一的 DamageInfo 组装点
private DamageInfo BuildDamageInfo(WeaponData data)
{
    DamageInfo info = new DamageInfo(data.damage, data.knockbackForce);
    if (data.burnDamagePerTick > 0 && data.burnDuration > 0f)
        info = info.WithAddedStatus(StatusEffectConfig.Burn(...));
    if (data.freezePercent > 0f && data.freezeDuration > 0f)
        info = info.WithAddedStatus(StatusEffectConfig.Freeze(...));
    return info;
}
```

**Decorator 类文件不删**——`BurningDecorator`、`FreezingDecorator`、`KnockbackDecorator` 仍然保留在项目中。它们的用武之地是**运行时组合**：

```csharp
// 未来场景：玩家捡到"灼烧附件"，对当前武器运行时包一层
weaponStrategy = new BurningDecorator(weaponStrategy, 3f, 5);
```

这和 SO 字段走的是两条路：SO 是"设计时配置",Decorator 是"运行时叠加"。两者互补而非互斥——但是现在装配线上只留一个入口(SO → BuildDamageInfo),避免重复翻译。
